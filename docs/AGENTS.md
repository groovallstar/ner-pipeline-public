# 문서 작업 지침

검증·리뷰·브랜치·커밋 절차는 루트 [AGENTS.md](../AGENTS.md)를 따른다.

## 문서 역할과 배치

- `docs/issues/`에는 AI가 작업을 이어가고 이력을 추적할 작업 기록을 둔다.
  이슈·작업 문서의 생성·갱신 절차와 양식은 [이슈 문서 지침](issues/AGENTS.md)을 따른다.
- `docs/manual/`에는 현재 구현의 사용·운영 방법과 데이터 스키마를 둔다.
  설계·요구사항·규약은 그 하위 `docs/manual/specs/`에 둔다.
- `docs/reports/`에는 사람에게 전달할 실험·평가 결과와 분석을 둔다.
- `docs/wiki/`에는 LLM Wiki 자료를 둔다. 위키 작업은 `docwiki` 스킬을 따른다.

## 공통 작성 기준

- 문서의 목적에 맞는 위치를 선택하고, 같은 주제의 기존 문서가 있으면 갱신한다.
- 상세 내용을 여러 문서에 중복 유지하지 않고, 필요한 요약과 원본 링크로 연결한다.
- 현재 기준과 과거 이력, 확인한 사실과 제안·미검증 사항을 구분한다.
- 결과와 수치의 근거·실행 조건은 루트의 평가와 검증 원칙에 따라 식별할 수 있게 한다.
- 문서를 추가하거나 이동할 때는 관련 참조와 상대 링크를 확인한다.

## 코드 변경에 따른 문서 갱신

- 변경으로 기존 설명이 달라지면 관련 문서를 함께 갱신한다. 동작·사용법·설정·운영
  방법은 관련 매뉴얼을, 코드 구조는 구현 맵을, 데이터 형식은 스키마 문서를 확인한다.
- 설계·요구사항·규약이 바뀌면 관련 spec의 현재 기준도 갱신한다.
