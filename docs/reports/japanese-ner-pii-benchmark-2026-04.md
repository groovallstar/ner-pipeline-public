## 3. 핵심 발견: gpt-5-mini 안전 필터 우회 (disclaimer 프롬프트)

초기 벤치에서 gpt-5-mini는 **PII 7종 엔티티를 전혀 인식하지 못했다**(모든 PII F1=0.0). 이후 `src/labelers/ja/ner_prompts.py:131`의 `SYSTEM_PROMPT` 프리앰블에 **합성 벤치마크 선언 + 태스크 성격 명시(추출만)** disclaimer를 추가하고 PII 타입 정의를 포함시키자 PII 엔티티가 정상적으로 반환되기 시작했다.

**원인·처방**:

- 초기 현상: OpenAI 안전 필터가 PII 포맷(이메일·전화·카드번호·ID) span을 출력에서 억제, Stockmark 원본 엔티티만 반환.
- 처방: SYSTEM_PROMPT 최상단에 **합성 PII 연구 벤치마크**임을 명시 (예시는 `example.com` 등 더미값, 학술 평가 목적의 정보 추출만, 거부·경고 응답 금지). 동시에 기존 SYSTEM_PROMPT에 누락되어 있던 **PII 타입 6종 정의**(EMAIL/PHONE/ADDRESS/DOB/ID_NUMBER/CREDIT_CARD)를 명시적으로 추가.
- 결과: 전체 F1 **0.6706 → 0.8709 (+0.200)**, Recall **0.6238 → 0.9223 (+0.299)**. PII 6종 모두 Stockmark 엔티티와 동등한 수준으로 회복.
- 남은 약점: **DOB 0.7021** — vLLM 모델(0.90+)보다 약 -0.2 낮음. gpt-5-mini는 "○년○月○日生" 같은 명시적 문맥 외에 일반 연도·날짜를 DOB로 잘못 포함/배제하는 경향.

→ **disclaimer 프롬프트를 쓰면 gpt-5-mini도 PII 포함 NER에 사용 가능**. DOB 중심 편차는 남아있어 Stockmark 원본 엔티티 위주 벤치에 우선.

## 6. 확인 사항

### (a) PII 인식 능력
vLLM 모델들은 프롬프트에 명시된 PII 타입(EMAIL, PHONE, ADDRESS 등)을 잘 인식한다. 특히 EMAIL·CREDIT_CARD·ID_NUMBER는 거의 모든 모델에서 F1 0.9 이상.

### (b) gpt-5-mini 안전 필터와 disclaimer 프롬프트
초기에는 PII 추출 태스크에서 안전 필터로 PII span이 억제 (모든 PII F1=0.0). **합성 벤치마크임을 명시하는 disclaimer + PII 타입 정의**를 SYSTEM_PROMPT 프리앰블에 추가하면 정상 추출 가능 (F1 0.6706 → 0.8709). 단, DOB는 여전히 0.7021로 vLLM 대비 약점.

### (c) DOB (생년월일)의 난이도
DOB는 모델별 편차가 큼 (gemma-31B: 0.971 vs Qwen-27B: 0.690). 날짜 형식(`2001.03.27`, `1985/12/03` 등) 다양성과 문맥 내 위치가 난이도를 높인다.

### (d) ADDRESS 인식
122B-GPTQ가 ADDRESS에서 F1 0.484로 크게 하락 (Recall 0.362). 반면 gemma-4-31B-it은 0.906. 일본 주소 형식의 패턴 다양성에 대한 모델별 강건성 차이가 크다.
