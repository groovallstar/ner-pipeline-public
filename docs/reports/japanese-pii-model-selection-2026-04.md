## 목적

### 데이터 증강

공개된 일본어 NER 데이터셋(Stockmark NER Wikipedia 등)에는 전화번호·메일·주민등록·카드번호 같은 **개인정보(PII)가 포함되어 있지 않다.** 그러나 본 파이프라인의 목표는 **텍스트에서 PII를 검출·마스킹**하는 것이므로, PII 엔티티가 라벨링된 학습 데이터가 반드시 있어야 한다. 실제 개인정보는 수집·공개할 수 없어 공개 데이터셋에서 얻을 수 없으므로, **합성 PII를 생성해 기존 NER 데이터에 주입**하는 증강이 유일한 현실적 경로이다.

### LLM 기반 주입

가장 단순한 방법은 규칙 기반 주입기(`src/augmenters/pii/injector.py`의 `PIIInjector`)로 문장의 **앞·뒤·랜덤 위치**에 PII 토큰을 삽입하는 것이다. 이 방식은 구현이 간단하지만 두 가지 위험이 있다.

1. **문맥 부자연** — "…である。 電話 090-1234-5678" 처럼 문장과 무관하게 끼워 넣으면, BERT의 **positional embedding**과 `[SEP]`·구두점 경계 토큰에 대한 self-attention이 결합해 "문두/문미 근처의 숫자열·@ = PII"라는 위치 기반 shortcut을 학습한다. 결과적으로 정규식 수준의 표면 패턴만 잡고, 문장 중간에 자연스럽게 등장하는 PII에는 일반화하지 못하는 shortcut learning 문제가 발생한다.
2. **주변 단서 결여** — 자연 문장에서 PII는 보통 「担当の○○」「連絡先は○○」처럼 trigger phrase와 함께 등장하는데, 랜덤 삽입에서는 이 단서가 사라져 **실제 문서에서는 PII가 등장해도 감지하지 못할 가능성**이 있다.

> 단, "단순 삽입이 실제로 얼마나 성능을 저하시키는가"는 본 벤치마크의 주제가 아니며, 후속 실험(규칙 기반 vs LLM 기반 학습 데이터로 파인튜닝한 BERT의 span F1 비교)에서 별도 검증이 필요하다.

이를 회피하기 위해 **LLM에게 "원문에 PII를 자연스러운 문맥으로 삽입하라"고 요청**해 학습 데이터를 만든다(`src/augmenters/pii/llm_injector.py`, 프롬프트 `_INJECTION_PROMPT` 참조).

### 본 벤치마크가 측정하는 것

LLM 기반 자연 주입 파이프라인은 **두 개의 LLM을 직렬로 사용**한다.

1. **Injector** (`LLMInjector`) — 원문에 PII를 자연스럽게 삽입하고 생성 텍스트에서 span offset을 추출한다.
2. **Verifier** (`PIIVerifier`) — 주입된 결과를 **독립적으로 재라벨링**하여, 주입 LLM이 만든 span이 실제로 자연 문맥에 녹아들어 PII·원본 엔티티 양쪽에서 재검출되는지 교차 검증한다. `policy=drop_span`으로 상충 span을 걸러낸다.

CLI(`src/augmenters/pii/__main__.py`)는 `--inject-url/--inject-model`과 `--verify-url/--verify-model`을 분리 지정할 수 있어, **성능이 가장 높은 상위 2개 모델을 각각 주입·검증 역할로 배치**하는 실제 워크플로우와 일치한다.

따라서 후보 모델은 다음 조건을 동시에 만족해야 한다.

- **PII 주입 전(Stockmark 원본 8종) span F1** — 주입 과정에서 기존 엔티티를 깨뜨리지 않을 기반선
- **PII 주입 후(8종 + 합성 PII 6종 = 15종) span F1** — 주입·검증 양쪽 역할에서 실제로 필요한 능력
- **1000샘플 단위 처리량** — 주입 1회 + 검증 1회 = 샘플당 2회 LLM 호출이 발생하므로 실용적 비용

아래 비교 리포트는 "주입 전후 동일 모델의 span F1 변화"를 나란히 두어, 주입 역할과 검증 역할에 투입할 상위 2개 모델을 선정하기 위한 기초 자료이다.

## 두 벤치의 역할 분담

| 벤치 | 데이터셋 | 확인하는 능력 |
|---|---|---|
| japanese-ner-benchmark | `stockmark/ner-wikipedia-dataset` test 1000 | PII 주입 대상인 **원본 엔티티 8종**에 대한 기본 NER 품질 — 주입 과정에서 기존 span을 깨뜨리지 않을 수 있는지 판단하는 기반선 |
| japanese-ner-pii-benchmark | `data/pii/stockmark_pii_1000.jsonl` (993 samples) | **주입 대상 태스크 자체의 최종 품질** — PII 6종을 포함해 총 15종에서 주입·검증 파이프라인이 실제로 유효한 span을 뽑아낼 수 있는지 |

원본 벤치는 "양자화/모델 선택이 기존 Stockmark 능력을 얼마나 훼손하는가"의 기반선을, PII 혼합 벤치는 "실제 주입 워크플로우에 투입했을 때의 기대 품질"을 보여준다. 두 측정이 나뉘어 있어야 PII 엔티티의 영향(평균 +0.07~0.10 F1 상승)이 원본 능력 때문인지 PII 패턴이 단순해서인지 분리해 해석할 수 있다.

## 선정 기준 (우선순위)

1. **PII 포함 Span F1** (주입 타겟 품질)
2. **Stockmark 원본 F1** (기존 엔티티 보존력)
3. **1000샘플 처리 시간 / sec/sample** (주입·검증 2회 호출 구조에서의 총 비용)
4. **VRAM·GPU 수** (동시 구동 시 실행 가능성)
5. **안전 필터 영향** (외부 API의 경우 disclaimer 프롬프트 필요 여부)

상세 권장 설정은 각 리포트의 최종 섹션("권장 설정")을 참조한다.
