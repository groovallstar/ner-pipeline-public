# /v1/ner 기능 부하 테스트

- 측정일: 2026-09-10.
- 대상: `POST http://127.0.0.1:18008/v1/ner`이며, 이 저장소의 서버를 기동하여 측정했다.
- 측정 커밋: `1f135b47ff1d5f5903755b7a4a7d11ee6c5c7902`.
- 구현 참조: [NER API](../../src/server/app.py), [서버 설정](../../src/server/config.py), [언어 탐지](../../src/server/detect.py)이다.

기존 측정 결과를 요약한 보고서이며, 이번 인용 정리에서는 테스트나 부하를 재측정하지 않았다. 언어 탐지 단위 테스트 49개는 최초 문서 작성 시 별도로 다시 실행한 결과이다.

인용은 Git이 추적하는 구현·테스트·문서로 한정한다. 측정 커밋은 당시 서버 구현을 식별하며, 부하 수치나 요청별 원본을 보관한 커밋은 아니다. 측정 스크립트·요청별 응답·실행 로그·모델 파일 식별 정보는 저장소에 보존되지 않으므로, 저장소만으로 당시 수치의 독립 재검산이나 동일 모델의 재현을 보장할 수 없다. 아래 수치는 명시한 실행 조건에서 관측한 요약 기록이다.

## 결과

- 실모델 기능 검사 30개가 통과했다. 4개 언어 명시·자동 감지, 긴 입력, 원문 NFC offset, 단건/혼합 배치 동일성, 64건 배치, 미지원·빈 입력, NFD·emoji, 400·413·422·405 응답을 검사했다.
- 부하 13단계의 4,363건 중 4,339건이 200, 포화 시험의 24건이 429였다. 5xx, 통신 오류와 정상 응답의 기준 결과 불일치는 없었다.
- 포화 시험은 8개 텍스트 배치 요청 64건을 동시에 전송했다. 40건이 처리되고 24건이 429로 거절되었다. 이후 40건 모두 정상 처리되고 health가 정상이었다. 즉시 복구 단계 p95는 33.1ms로 초기보다 높았다.
- 이후 별도 15초 순차 재측정은 1,063건이 모두 정상 처리되었다. 처리량 70.83요청/초, p95 14.65ms였다. 이 후속 검사는 동기 httpx.Client를 사용했으므로 주 측정의 비동기 클라이언트와 완전히 같은 조건은 아니다.
- 모델 없는 기존 서버 검사는 164 passed, 1 warning이었다. Ruff와 git diff --check가 통과했다.

## 주요 부하 수치

### 표의 용어와 계산 기준

| 항목 | 의미와 계산 기준 |
|---|---|
| 텍스트 1건 | `text`의 문자열 하나 또는 `texts` 배열의 원소 하나이다. 문자열에 여러 문장이 있어도 1건이며, 글자 수나 토큰 수로 정규화한 단위가 아니다. 데이터의 row 하나를 문자열 하나로 보내면 텍스트 1건이 row 1개에 해당한다. |
| 요청당 텍스트 | HTTP 요청 한 번에 보내는 문자열 개수이다. 단건 요청은 1개이고, 이번 배치 요청은 8개이다. |
| 동시 요청 | 클라이언트가 동시에 응답을 기다릴 수 있는 HTTP 요청 수의 상한이다. 서버에서 동시에 실행하는 추론 수와 같지는 않으며, 서버의 추론 슬롯이 차면 요청이 대기할 수 있다. |
| 요청 수 | 해당 단계에서 응답 또는 통신 오류까지 기록한 HTTP 요청의 총수이다. 텍스트 수가 아니며, 아래 지속 부하 표에서는 모두 HTTP 200이었다. |
| 성공 요청/초 | HTTP 200이고 응답 검증도 통과한 요청 수를 단계의 실제 경과 시간(초)으로 나눈 값이다. |
| 텍스트/초 | 성공 요청 수 × 요청당 텍스트 수 ÷ 단계의 실제 경과 시간(초)이다. 실패하거나 429로 거절된 요청의 텍스트는 포함하지 않는다. |
| p50 ms | 검증된 HTTP 200 요청의 지연 중앙값이다. 요청을 보내기 직전부터 응답 본문 수신까지의 클라이언트 관측 시간이며, JSON 파싱·응답 검증·결과 파일 기록 시간은 포함하지 않는다. |
| p95 ms / p99 ms | 검증된 HTTP 200 요청의 95% / 99%가 각각 이 시간 이내에 응답했다는 뜻이다. 지연을 정렬한 뒤 `ceil(표본 수 × 비율)`번째 값을 쓰는 nearest-rank 방식으로 계산했다. |

8건 배치·동시 요청 1의 **23.58요청/초 × 8텍스트/요청 = 약 188.67텍스트/초**이다. 반올림 전 수치로 계산했으며, row 하나가 문자열 하나라면 약 189row/초를 처리한 것이다. 배치의 p95 42.80ms는 텍스트 하나가 아니라 8개 전체를 담은 요청 한 번의 지연이다.

각 단계는 새 요청을 15초 동안 발행한 뒤 진행 중인 요청을 모두 회수했다. 처리량의 분모에는 마지막 요청 회수와 클라이언트의 응답 검증·파일 기록 시간도 포함되므로, 위 요청별 지연의 측정 구간과 다르다.

## 언어 탐지 테스트 결과

### HTTP 자동 탐지

`lang`을 생략하여 서버가 언어를 선택하도록 했다. 아래 4개 고정 예문은 각 언어의 명시 지정 요청과 자동 탐지 요청에서 같은 NER 응답을 반환했으며, 모든 자동 탐지 요청이 HTTP 200으로 처리되었다. 이 예문들을 부하 테스트에서도 반복 사용했다.

| 기대 언어 | 실제 입력 문자열 | 문자 수 | 반환 언어 | 결과 |
|---|---|---:|---|---|
| `ja` | 織田信長は東京都千代田区に住んでいた。電話番号は090-1234-5678です。 | 40 | `ja` | 통과했다. |
| `ko` | 김민준은 서울대학교를 졸업하고 삼성전자에서 근무한다. 전화번호는 010-1234-5678이다. | 52 | `ko` | 통과했다. |
| `vi` | Nguyễn Văn An sống tại Hà Nội. Số điện thoại là 0904-123-456. | 61 | `vi` | 통과했다. |
| `en` | Barack Obama was born in Hawaii in 1961. Contact alice@example.com. | 67 | `en` | 통과했다. |

문자 수는 Python `len(text)` 기준으로 공백·문장부호를 포함하며, UTF-8 바이트 수나 모델 토큰 수가 아니다. 각 예문은 여러 문장을 포함할 수 있지만 텍스트 1건으로 계산했다.

| 추가 검사 | 기대 결과 | 실제 결과 |
|---|---|---|
| 4개 언어 예문을 순서대로 배치 전송했다. | 결과 언어가 입력 순서대로 `ja, ko, vi, en`이어야 한다. | 입력 순서를 유지했고 단건 응답과 일치했다. |
| 위 4개 예문을 16회 반복하여 64건 배치로 전송했다. | 각 항목의 자동 탐지 결과와 NER 응답이 단건 결과와 같아야 한다. | 64개 항목 모두 일치했다. |
| 숫자와 emoji만 있는 `12345 😀`를 전송했다. | `unsupported`와 빈 엔티티 목록을 반환해야 한다. | HTTP 200과 기대한 응답을 반환했다. |
| 빈 문자열을 전송했다. | `unsupported`와 빈 엔티티 목록을 반환해야 한다. | HTTP 200과 기대한 응답을 반환했다. |
| 일본어 예문·`12345 😀`·한국어 예문을 배치 전송했다. | 결과 언어가 `ja, unsupported, ko`이어야 한다. | 순서와 각 항목의 응답이 일치했다. |
| `lang: "th"`를 명시했다. | 자동 탐지를 하지 않고 미지원 언어 지정 오류를 반환해야 한다. | HTTP 400과 `unsupported lang 'th'` 오류를 반환했다. |

위 표는 당시 HTTP 검사 결과의 요약이며, 요청별 응답은 저장소에 보존되지 않았다. 마지막 행은 자동 탐지 정확도가 아니라 언어 지정 검증을 확인한 것이다. 요청 계약은 [NER API 구현](../../src/server/app.py)과 [API 계약 테스트](../../tests/server/test_api.py)를 참고한다.

### 탐지 규칙 단위 테스트

문서 작성 시 `uv run pytest tests/server/test_detect.py -q -rs`를 별도로 실행하여 **49개가 통과했다.** 이 결과는 기존 서버 검사 164개에 포함된 테스트를 다시 실행한 것이므로 49개를 독립 검사로 더해 합산하지 않는다. 검사 항목은 Git이 추적하는 [언어 탐지 테스트](../../tests/server/test_detect.py)에서 확인할 수 있다. 당시 실행 로그는 저장소에 보존되지 않았다. 이 검사는 HTTP나 모델 추론을 실행하지 않고 언어 탐지 함수를 직접 검사한다.

| 검사 범위 | 확인한 결과 |
|---|---|
| 일본어·한국어 고유 문자 | 히라가나·가타카나는 `ja`, 한글 음절·자모는 `ko`가 되었다. 가나와 한글이 함께 있으면 `ja`가 우선했다. |
| 베트남어 변별 문자 | horn·dot-below·đ 신호와 NFD 분해 입력을 `vi`로 판정했다. 베트남어에 한자가 섞여도 해당 신호를 유지했다. |
| 라틴 문자 폴백 | 다른 탐지 신호가 없는 라틴 문자는 `en`이 되었다. 영어 외 프랑스어·독일어·포르투갈어·스페인어·튀르키예어, 무부호 베트남어와 로마자 일본어도 `en`으로 보내는 현행 규칙을 확인했다. |
| 미지원 문자·빈 입력 | 한자만 있는 입력, 키릴 문자, 아랍 문자, 숫자·기호, 공백과 빈 문자열을 `unsupported`로 판정했다. |
| 문자 판별·확장 순서 | 범라틴 부호를 베트남어 신호로 오인하지 않았으며, 전각 라틴 글자와 수학 기호를 구분했다. 테스트에서 추가한 탐지기가 라틴 폴백보다 먼저 적용되는 것도 확인했다. |

### 해석의 한계

4개 고정 예문의 자동 탐지 성공과 규칙 테스트 통과는 다양한 실제 문서의 언어 탐지 정확도를 뜻하지 않는다. `en`은 다른 고유 신호가 없을 때 라틴 문자를 받아들이는 폴백이므로, 실제 영어라는 보장이 없다. 예를 들어 단위 테스트의 짧은 베트남어 `Xin chào`는 `en`으로 판정된다. 이는 현행 규칙에 맞아 테스트가 통과한 것이며 올바른 언어 분류를 뜻하지 않는다. HTTP NFD 검사는 `lang: "vi"`를 지정했으므로 자동 탐지 증거에 포함하지 않았다. 탐지 규칙과 수용된 한계는 [언어 탐지 문서](../manual/language-detection.md)를 참고한다.

## 실행 조건과 한계

- 저장소 커밋: `1f135b47ff1d5f5903755b7a4a7d11ee6c5c7902`. 서비스 소스 변경은 없다. 사용자 소유의 기존 문서 변경은 유지했다.
- NVIDIA RTX A6000 GPU 0을 사용했다. 기동 전 GPU 0은 1MiB, 이용률 0%였다. 다른 GPU에서는 별도 작업이 실행 중이었다. 호스트 CPU·메모리는 독점하지 않았고 초반 측정 동안 모델 파일 fingerprint 수집 및 기본 pytest도 실행되었다. GPU 관측은 측정 중 일부 구간의 샘플이며 전체 실행의 최대치를 보장하지 않는다.
- 지원 언어는 ja/ko/vi/en이며 `/data/ner/{lang}/model`을 로드했다. ja만 threshold 파일이 로드되었다. 모델 가중치와 파일별 식별 정보는 저장소에 보존되지 않았다.
- `CUDA_VISIBLE_DEVICES=0`, HF/Transformers offline 모드, 번역 비활성, API key 미설정으로 실행했다. 기존 NER_SERVER_* 환경변수를 제거하고 기본값을 사용했다. 동시 추론 8, 큐 32, acquire timeout 10초, max_length 256이다.
- 언어당 고정 합성 문장 하나를 반복했다. 지속 부하는 4개 언어를 순환하며, 배치는 언어당 2개씩 총 8개이다. 언어별 짧은 선행 측정은 각 80건이며, 지속 단계 전에 언어당 5건을 warmup했다.
- 클라이언트는 서버와 같은 호스트에서 keep-alive HTTP를 사용했다. 주 측정은 closed-loop 방식이며 고정 도착률 시험이 아니다. 요청 응답·검증·JSONL 기록 뒤 다음 요청을 보낸다. 처리량의 시간에는 이 부가 비용과 마지막 요청 회수가 포함된다.
- 실제 업무 입력 분포, 장문 지속 부하, 장시간 soak, 다중 호스트 네트워크, 인증 활성 상태, CUDA OOM 한계 및 acquire timeout에 의한 429는 별도로 검증하지 않았다. 관측한 429는 큐 포화 경로이다. NER 정확도/F1를 평가한 시험은 아니며, 성능 SLO가 주어지지 않아 성능 합격선을 임의로 설정하지 않았다.

## 검증 범위와 재실행

Git이 추적하는 검사 코드를 실행하는 명령은 다음과 같다. 이는 API 계약과 탐지 규칙을 다시 검사하는 명령이며, 위 HTTP 부하 수치를 재현하는 하네스는 아니다.

```bash
uv run pytest tests/server/test_detect.py -q -rs
uv run pytest tests/server -q -rs --ignore=tests/server/test_inference_integration.py --ignore=tests/server/test_live_server.py
```

- [모델 통합 테스트](../../tests/server/test_inference_integration.py)와 [기존 live 테스트](../../tests/server/test_live_server.py)는 기본 검사에서 명시적으로 제외했다. 당시 실모델 기능·부하 검사는 별도 HTTP 측정으로 수행했으며, 해당 측정 코드는 저장소에 보존되지 않았다.
- 기본 검사에서 관측한 경고 하나는 Starlette TestClient의 httpx 사용 deprecation이었다. 당시 Ruff와 `git diff --check`도 통과했으나 실행 로그는 저장소에 보존되지 않았다.
- 측정 시에는 요청 수·상태·오류·지연·처리량을 대조하고, 포화 시 429가 발생했는지와 이후 40건이 정상 처리되었는지를 확인했다. 리뷰에서 지적한 실패 판정 누락을 보완한 뒤 재리뷰를 마쳤다. 이 보고서의 요약 수치는 당시 검증 결과이며, Git이 추적하는 코드가 그 수치 자체의 증거를 대신하지는 않는다.
- 테스트 서버는 측정 후 종료했으며, 서비스 코드 변경·커밋·배포는 수행하지 않았다.
