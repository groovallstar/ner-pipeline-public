# Wiki Schema (LLM-Wiki)

이 문서는 `wiki/`의 구조와 운영 규칙을 정의한다. 본 위키는 **Andrej Karpathy의 LLM-Wiki** 모델을 따른다 — LLM이 직접 위키를 작성·관리하여 지식을 영속적으로 축적하고, 매 질문마다 원문을 재추출하지 않는다.

> 참고: https://news.hada.io/topic?id=28208

## 3계층 아키텍처

| 계층 | 역할 | 이 위키에서의 위치 |
|------|------|-------------------|
| **원문 소스(Sources)** | 불변의 기사·논문·데이터. 읽기 전용 외부 자료. | `sources/*.md` (외부 원문의 요약 노트) |
| **위키(Wiki)** | LLM이 생성·관리하는 구조화된 지식. 개념·엔티티·주제 페이지. | `concepts/*.md` |
| **스키마(Schema)** | LLM에게 구조·컨벤션을 알려주는 설정 문서. | 이 파일 `schema.md` |

본 위키는 프로젝트 독립 레이어이므로 호스트 저장소의 구체 내용(코드 경로·스크립트·결과 파일명)은 포함하지 않는다.

## 디렉토리 구조

```
wiki/
├── schema.md         # 이 문서 (스키마 계층)
├── concepts/         # 위키 계층: LLM이 유지하는 개념·방법론 페이지
├── sources/          # 원문 소스 계층: 외부 자료 요약 노트
├── index.md          # (선택) 전체 페이지 카탈로그
└── log.md            # (선택) 인제스트·린트 로그
```

`index.md`, `log.md`는 위키 규모가 커질 때 도입한다. 초기 단계에서는 없어도 된다.

## 페이지 유형

| 유형 | 위치 | 설명 |
|------|------|------|
| **개념** | `concepts/` | LLM이 요약·통합·갱신하는 구조화 지식 (이론, 방법론, 전략) |
| **소스** | `sources/` | 원문 1건당 1파일. 핵심 요지 + 출처 메타데이터 |

## 수록 원칙

1. **프로젝트 독립성**: 특정 저장소의 파일 경로·스크립트·결과 파일명을 포함하지 않는다.
2. **개발·기술 내용**: 재사용 가능한 지식(이론·알고리즘·방법론·원문 요약)만 담는다.
3. **LLM 관리 대상**: `concepts/`는 LLM이 인제스트/린트 과정에서 계속 갱신한다. 사람 편집도 가능하나, 구조 일관성은 스키마 규칙을 따른다.

## 3대 작업 (Operations)

LLM-Wiki의 세 가지 핵심 작업이다. 각각 트리거와 절차가 정해져 있다.

### 1. 인제스트 (Ingest) — 새 소스 추가

**트리거**: 새 논문·기사·블로그·데이터를 위키에 반영할 때.

**절차**:
1. 원문을 읽고 핵심을 추출
2. `sources/<slug>.md`에 원문 요약 노트 작성 (템플릿 §페이지 템플릿 참조)
3. 기존 `concepts/` 페이지 중 이 소스가 갱신해야 할 페이지를 식별 — 10~15개까지도 연쇄적으로 업데이트될 수 있음
4. 새 개념이 등장하면 `concepts/<slug>.md`를 신규 생성
5. 관련 페이지 간 교차 참조 추가 (§교차 참조 규칙)
6. `log.md`가 있다면 한 줄 기록

### 2. 쿼리 (Query) — 지식 조회

**트리거**: 위키 기반 질문·답변이 필요할 때.

**절차**:
1. 질문과 관련된 `concepts/` 페이지를 찾는다 (`index.md`가 있으면 우선 활용)
2. 해당 개념의 주장을 근거로 답변을 합성한다
3. 답변에 인용한 `concepts/` 및 `sources/` 페이지 경로를 명시한다
4. 위키에 정보가 없거나 낡아 보이면 인제스트 트리거로 연결

### 3. 린트 (Lint) — 품질 유지

**트리거**: 주기적(예: 월 1회) 또는 대규모 인제스트 직후.

**점검 항목**:
- 모순된 진술 (같은 사실에 대한 불일치)
- 낡은 주장 (새 소스로 대체되어야 하는 내용)
- 고아 페이지 (어디서도 참조되지 않는 페이지)
- 누락된 참조 (개념 페이지가 `sources/`를 인용하지 않음)
- 끊어진 링크
- 수록 원칙 위반 (프로젝트 경로·스크립트·결과 파일명 등장)

**결과**: 수정 커밋과 `log.md` 기록.

## 교차 참조 규칙

- 위키 내 참조는 `wiki/` 기준 상대 경로
  - 예: `` `concepts/bio-tagging.md` ``, `` `sources/park-2021-klue.md` ``
- `concepts/` 페이지는 자신의 주장을 뒷받침하는 `sources/` 파일을 반드시 인용한다
- `sources/` 페이지는 자신을 인용하는 `concepts/` 페이지를 역링크로 기록한다
- 외부(호스트 저장소) 참조는 위키에 직접 기재하지 않는다 — 호스트 저장소 쪽에서 링크한다

## 페이지 템플릿

### `concepts/*.md`

```markdown
# <개념명>

> 한 줄 요약

## 개요
## 핵심 원칙
## 세부 설명
## 출처
- `sources/<file>.md` — <이 출처에서 가져온 핵심>
```

### `sources/*.md`

```markdown
# <저자> (<연도>) — <제목>

- **저자**:
- **연도**:
- **매체/학회**:
- **링크**:
- **유형**: 1차 문헌 | 2차 자료

## 핵심 요지

## 주요 내용

## 인용하는 위키 페이지
- `concepts/<file>.md`
```

### (선택) `index.md`

전체 페이지 카탈로그. 임베딩 없이도 LLM이 관련 페이지를 빠르게 찾도록 돕는다.

```markdown
# Index

## Concepts
- `concepts/bio-tagging.md` — BIO/IOB 태그 체계와 span 변환
- `concepts/token-management.md` — LLM 컨텍스트 운영 전략
- ...

## Sources
- `sources/ramshaw-marcus-1995-bio-tagging.md` — BIO 스킴 원조 논문
- ...
```

### (선택) `log.md`

인제스트·린트 이력의 시간순 로그.

```markdown
# Log

## 2026-04-13
- Ingest: addyosmani/agent-skills → concepts/agent-skills.md 생성, sources/addyosmani-agent-skills.md 작성
- Lint: bio-tagging.md 내 끊어진 참조 1건 수정
```
