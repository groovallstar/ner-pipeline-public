# 언어 자동 감지

`POST /v1/ner`는 요청에 언어를 지정하지 않으면 텍스트에 포함된 문자와 부호를
보고 사용할 NER 모델을 정합니다. 현재 지원 언어는 일본어(`ja`), 베트남어(`vi`), 한국어(`ko`), 영어(`en`)입니다.

감지기는 문장의 뜻이나 단어를 분석하지 않습니다. 정해진 문자 범위를 검사하는
규칙으로 동작하며, 별도의 언어 식별 모델이나 외부 서비스를 사용하지 않습니다.
따라서 반환된 언어가 원문의 실제 언어와 항상 같지는 않습니다.

## 1. 언어를 지정하는 방법

원문의 언어를 알고 있다면 `lang`을 지정하면 됩니다. 서버는 자동 감지를 건너뛰고
지정한 언어의 모델로 추론합니다. 텍스트가 실제로 그 언어인지 별도로 확인하지는
않습니다.

```json
{"text": "Xin chào", "lang": "vi"}
```

`lang`을 생략하거나 `null`로 보내면 자동 감지를 사용합니다.

```json
{"text": "Xin chào"}
```

이 입력은 현재 규칙에서 영어(`en`)로 판정됩니다. `chào`의 악센트는 베트남어
감지에 사용하는 부호가 아니기 때문입니다. 이런 경우에는 첫 번째 요청처럼
언어를 직접 지정해야 원하는 모델을 사용할 수 있습니다.

`lang`에는 지원 언어 코드만 지정할 수 있습니다. 빈 문자열, `auto`,
`unsupported` 또는 그 밖의 코드를 지정하면 HTTP 400으로 응답합니다.
`unsupported`는 자동 감지의 결과로만 사용합니다.

## 2. 자동 감지 순서

서버는 다음 표를 위에서부터 확인하고, 처음 만족하는 조건의 언어를 선택합니다.


| 순서  | 확인하는 내용                       | 결과            |
| --- | ----------------------------- | ------------- |
| 1   | 가나(仮名) 범위에 속하는 문자가 하나라도 있는가?  | `ja`          |
| 2   | 한글 범위에 속하는 문자가 하나라도 있는가?      | `ko`          |
| 3   | 베트남어 감지용 부호 또는 `đ`·`Đ`가 있는가?  | `vi`          |
| 4   | 검사 대상인 라틴 문자 범위에 속하는 글자가 있는가? | `en`          |
| 5   | 위 조건을 모두 만족하지 않는가?            | `unsupported` |


문자의 개수나 비율은 비교하지 않습니다. 영어 문장이 길어도 가나가 한 글자
있으면 `ja`가 됩니다. 여러 언어가 섞인 텍스트도 하나의 언어로 판정하며,
언어별로 구간을 나누어 추론하지 않습니다.

영어는 앞의 세 규칙에 해당하지 않는 라틴 문자 입력을 받는 기본값입니다.
이 처리를 **폴백**이라고 합니다. 영어를 확인한 결과가 아니라, 라틴 문자는
있지만 앞 단계에서 언어를 정하지 못했다는 뜻입니다.


| 입력                       | 감지 결과         | 이유                            |
| ------------------------ | ------------- | ----------------------------- |
| `東京は晴れです。`               | `ja`          | 히라가나가 있습니다.                   |
| `나는 학교에 간다.`             | `ko`          | 한글이 있습니다.                     |
| `ㅋㅋㅋ`                    | `ko`          | 한글 호환자모도 검사합니다.               |
| `Tôi là người Việt Nam.` | `vi`          | 베트남어 감지용 부호가 있습니다.            |
| `hello world`            | `en`          | 앞의 세 조건에 해당하지 않고 라틴 글자가 있습니다. |
| `Bonjour à tous`         | `en`          | 프랑스어도 같은 폴백을 적용받습니다.          |
| `Xin chào`               | `en`          | 베트남어 감지용 부호가 없습니다.            |
| `東京都千代田区`                | `unsupported` | 한자만으로는 언어를 정하지 않습니다.          |
| `Привет мир`             | `unsupported` | 키릴 문자 감지 규칙이 없습니다.            |
| `12345 !!!`              | `unsupported` | 감지에 사용하는 문자나 부호가 없습니다.        |
| 빈 문자열 또는 공백만 있는 문자열      | `unsupported` | 감지 신호가 없습니다.                  |
| `한국어와 日本語のテキスト`          | `ja`          | 가나를 한글보다 먼저 검사합니다.            |
| `한국어 Việt`               | `ko`          | 한글을 베트남어 부호보다 먼저 검사합니다.       |


## 3. 언어별로 검사하는 신호

### 일본어: 가나 범위

히라가나, 가타카나, 가타카나 음성확장, 반각 가타카나 범위를 검사합니다.
한자는 검사하지 않으므로 일본어라도 한자만 있으면 `unsupported`가 됩니다.
로마자로 쓴 일본어인 `Watashi wa gakusei desu`는 `en`으로 판정됩니다.

검사는 문자 범위를 기준으로 하므로 그 안에 있는 기호도 포함됩니다.
예를 들어 가타카나 중점 `・`와 장음부 `ー`가 신호로 작용합니다.
`Jon・Grant`도 실제 언어와 관계없이 `ja`로 판정됩니다.

### 한국어: 한글 음절과 자모 범위

완성된 음절뿐 아니라 조합용 자모, 호환자모, 옛한글 자모 확장 범위,
반각 한글도 검사합니다. 그래서 `가나다`와 `ㅋㅋㅋ`를 모두 감지합니다.

한글과 한자가 섞인 `大韓民國 국민은 모두 평등하다.`는 `ko`입니다.
다만 같은 입력에 가나까지 있으면 먼저 검사하는 일본어 규칙이 적용됩니다.

### 베트남어: 특정 부호와 문자

다음 네 가지 신호 중 하나라도 있으면 `vi`로 판정합니다.


| 신호              | 코드포인트          | 예시            |
| --------------- | -------------- | ------------- |
| horn 결합부호       | U+031B         | `ơ`, `ư`      |
| hook above 결합부호 | U+0309         | `ả`, `ẻ`, `ỉ` |
| dot below 결합부호  | U+0323         | `ạ`, `ẹ`, `ị` |
| 획이 있는 d         | U+0111, U+0110 | `đ`, `Đ`      |


검사할 때는 NFD 정규화를 사용합니다. 이는 조합된 글자를 기본 글자와 결합부호로
분리하는 방식입니다. 예를 들어 `ạ`와 `a` 뒤에 dot below를 붙인 입력을
같은 신호로 인식합니다. 이 정규화는 감지 함수 안에서만 사용하며, 추론에 넘기는
원문을 바꾸지 않습니다.

acute, grave, circumflex, tilde 같은 부호만으로는 베트남어로 판정하지 않습니다.
`café`, `naïve`, `Zürich`, `mañana`, `João`는 베트남어 규칙에 걸리지 않고
`en` 폴백으로 갑니다.

이 규칙은 부호가 베트남어 단어에 쓰였는지 확인하지 않습니다. 다른 언어의 입력에
같은 부호가 있어도 `vi`가 될 수 있으며, dot below 결합부호 하나만 넣어도
`vi`가 됩니다. 따라서 베트남어 오분류가 없다고 보장할 수 없습니다.

### 영어: 라틴 문자 폴백

앞의 세 규칙에 해당하지 않으면 ASCII 영문자와 일부 확장 라틴 문자,
전각 영문자를 검사합니다. 하나라도 있으면 `en`입니다.

프랑스어 같은 다른 라틴 문자 언어, 부호를 제거한 베트남어,
로마자로 적은 일본어도 이 경로로 들어옵니다. 또한 한자나 키릴 문자로 된
텍스트에 ASCII 영문 이름이나 URL이 섞이면 `en`이 될 수 있습니다.

확장 라틴 문자 중 `ế`는 베트남어 감지용 부호가 없어 `en`으로 갑니다.
반면 `ộ`는 dot below가 있으므로 라틴 폴백에 도달하기 전에 `vi`로 결정됩니다.
곱셈 기호 `×`와 나눗셈 기호 `÷`는 라틴 문자 범위에서 제외합니다.

## 4. 감지 결과와 API 응답

자동 감지 결과가 지원 언어이면 해당 모델로 NER 추론을 수행합니다.
`unsupported`이면 모델을 호출하지 않고 다음과 같이 HTTP 200으로 응답합니다.

```json
{"lang": "unsupported", "entities": []}
```

이는 현재 규칙으로 추론할 언어를 선택하지 못했다는 뜻입니다.
원문에 개체명이 없다는 판단은 아닙니다.

배치에서 `lang`을 생략하면 각 항목을 따로 감지합니다.

```json
{"texts": ["東京は晴れです。", "東京都千代田区", "Hà Nội là thủ đô."]}
```

위 요청의 결과에는 `ja`, `unsupported`, `vi`가 입력 순서대로 들어갑니다.
가운데 항목의 `entities`는 빈 목록이고 나머지 항목은 각 언어 모델로 추론합니다.
배치 요청에 `lang`을 지정하면 모든 항목에 그 언어를 적용합니다.

`unsupported`와 모델 미로드는 다릅니다. 감지되거나 지정된 언어의 모델이
로드되어 있지 않으면 HTTP 503으로 응답합니다. 배치에서도 필요한 모델 하나가
없으면 요청 전체가 503이 되며, 성공한 항목만 반환하지 않습니다.

## 부록: 검사하는 문자 범위

아래 범위는 양 끝을 포함합니다. 구현은 유니코드 스크립트 속성이나 단어 사전을
조회하지 않고 코드포인트가 이 범위 안에 있는지 비교합니다.
따라서 블록 안의 기호도 감지될 수 있고, 표에 없는 문자 범위는 검사하지 않습니다.


| 용도                        | 범위                                          |
| ------------------------- | ------------------------------------------- |
| 히라가나                      | U+3040–U+309F                               |
| 가타카나                      | U+30A0–U+30FF                               |
| 가타카나 음성확장                 | U+31F0–U+31FF                               |
| 반각 가타카나                   | U+FF66–U+FF9D                               |
| 한글 자모                     | U+1100–U+11FF                               |
| 한글 호환자모                   | U+3130–U+318F                               |
| 한글 자모 확장 A                | U+A960–U+A97F                               |
| 한글 음절                     | U+AC00–U+D7A3                               |
| 한글 자모 확장 B                | U+D7B0–U+D7FF                               |
| 반각 한글                     | U+FFA0–U+FFDC                               |
| ASCII 영문자                 | U+0041–U+005A, U+0061–U+007A                |
| Latin-1의 검사 대상            | U+00C0–U+00D6, U+00D8–U+00F6, U+00F8–U+00FF |
| Latin Extended-A·B        | U+0100–U+024F                               |
| Latin Extended Additional | U+1E00–U+1EFF                               |
| 전각 영문자                    | U+FF21–U+FF3A, U+FF41–U+FF5A                |


예를 들어 IPA Extensions와 Latin Extended-C·D·E는 라틴 폴백 범위에 없습니다.
다만 원문이 이 표의 범위 밖에 있어도, NFD로 분해한 결과에 베트남어 감지용
부호가 생기면 베트남어 규칙에 걸릴 수 있습니다.
