# Canonical Entity Schema (JA · VI · KO · EN)

JA·VI·KO·EN 이 공유하는 통합 엔티티 라벨 공간. NER/PII 구분 없이 **10종
평면 목록**을 OntoNotes 관용 영문 축약으로 표기한다.

## 1. 10종 canonical 정의 (평면 목록)

| Label | 의미 | 정의 | JA 예시 | VI 예시 |
|---|---|---|---|---|
| `PER` | 인물 | 사람 이름(풀네임·성·이름·별명·예명). 직함·호칭은 제외 | `織田信長`, `田中` | `Nguyễn Xuân Phúc`, `Hồ Chí Minh` |
| `LOC` | 지명·주소·경로 | 국가·행정구역·자연지명(산·강·바다·섬·호수)·주소(번지·건물·층수 포함)·여러 지점을 잇는 경로(철도·지하철 노선·도로). **한 자리에 선 인공 시설은 ORG로 분류** (**KO 는 §2.5 로 더 좁다** — 시설·경로를 아예 안 뽑는다) | `東京`, `富士山`, `東京都千代田区1丁目2-3`, `JR京都線` | `Hà Nội`, `Vịnh Hạ Long`, `Sông Hồng`, `Quốc lộ 1A` |

| `EVT` | 행사·사건 | 1회성 공식 행사·전쟁·조약·대회·자연재해·named 위기·주기적 선거/투표 (지속 운영리그·팀은 `ORG`, 경기·컵은 EVT — 회색지대 §3.3) | `関ヶ原の戦い`, `第45回NHK紅白歌合戦`, `東日本大震災`, `総選挙` | `Chiến tranh Việt Nam`, `UEFA Champions League 2007-08` |

| `PHONE` | 전화번호 | 국내·국제 전화번호 (하이픈·공백·국가번호 허용) | `090-1234-5678`, `+81 80 1234 5678` | `+84 90 1234567` |
| `ID_NUM` | 개인 식별 번호 | 마이넘버·CCCD·세무번호·사원번호·주민등록번호 등 개인 식별 숫자열 | `284257239645` | `079123456789` |
| `CREDIT_CARD` | 신용카드 번호 | 13~19자리 카드 번호 (공백·하이픈 구분자 허용) | `4065 0551 3022 4539` | (공통) |

> 출력 라벨은 `DEFAULT_MERGE_RULES` 의 `'ADDRESS': 'LOC'` 무조건 병합
> 규칙에 의해 전부 `LOC` 로 변환되어 학습 데이터에 반영된다.

## 2. LOC vs ORG 경계 규칙

### 2.1 2단 판정 원칙 (공통)

NER 5종 경계는 다음 두 축으로 단순화한다:

1. **LOC** — **지리적 위치 자체**: 국가·행정구역·자연지명·주소(번지·
   건물·층수 포함) + 여러 지점을 잇는 경로(철도·지하철 노선·도로·
   고속도로). 한 자리에 선 인공 시설(역·공항·건물·교육기관 등)은
   **제외**.
2. **ORG** — **조직·시설 일체**: 기업·법인·정당·정부·군대·국제
   기관·스포츠팀·학회·협회 + 역·공항·교량·터널·병원·학교·대학·
   점포·박물관·도서관·연구소·종교시설 등 개별 구조물인 인공 시설.

**이 두 축은 JA·VI·EN 것이다 — KO 는 §2.5 가 따로 정한다.** KO 는 인공 시설을
ORG 에 넣지 않고 아예 안 뽑으며, ORG 도 정부·행정·공공·정치 기관으로 좁힌다.

행정 지명 복합체(예: `東京都`, `Thành phố Hồ Chí Minh`)는 행정구역(LOC)과
지방정부 조직(ORG)을 모두 가리킬 수 있다. **표면형이 지칭하는 구체
대상**으로 결정한다. `東京都` 가 행정구역을 지칭하면 LOC, 지방정부 조직을
지칭하면 ORG.

### 2.2 라벨 우선순위 (모호할 때 위에서 아래로)

| 순위 | 판정 | 적용 대상 |
|---|---|---|
| 1 | **`ORG`** | 조직·법인·공권력 + 개별 구조물인 인공 시설 (KO 는 §2.5) |
| 2 | **`LOC`** | 지리적 위치만 — 국가·행정구역·자연지명·주소·경로(노선·도로) (KO 는 §2.5) |
| 3 | **`PROD`** | 상품·작품·방송 프로그램 (무형 서비스는 §3.2 로 비-entity) |
| 4 | **`EVT`** | 1회성 행사·전쟁·조약·대회 |

**이 표는 폴백이다** — §3 이후가 정한 개별 규칙이 있으면 그쪽이 이긴다. 표를
먼저 적용하면 §3.1 이 `EVT` 로 보내는 named 프로젝트가 순위 3 에서 `PROD` 로
멈추고, §3.2 가 비-entity 로 빼는 것들은 이 표에 자리가 없어 갈 곳을 잃는다.

추가 원칙:
- **대학**: 본체·캠퍼스·부속시설 모두 ORG. `○○大学病院` 도 ORG.
- **행정구역 복합체**: `東京都千代田区` 같은 복합체는 단일 LOC 한 덩어리.
- **복합 조직명**: 리그명+팀명 등은 분리하지 않고 한 덩어리.
- **번지 포함 주소**: `東京都千代田区1丁目2-3 ビル7F` 처럼 번지·층 포함도
  LOC (별도 ADDRESS 타입 없음).

### 2.4 VI 핵심 경계 케이스

**LOC (자연·행정·경로)**:
- 국가·도시·tỉnh·huyện·xã
- 자연지명: `Sông X` / `Núi X` / `Biển X` / `Đảo X` / `Vịnh X` / `Hồ X`
- 주소 (số nhà, tầng, tòa nhà 포함)
- 경로 인프라: `Quốc lộ X` / `Đường cao tốc X` / `Đường sắt X` /
  `Tàu điện ngầm X tuyến N`

**ORG (모든 조직·인공시설)**:
- 영리법인: `Công ty X` / `Tập đoàn X` / `Ngân hàng X` / `Hãng X` /
  `Đài truyền hình X`
- 정치·정부·군: `Đảng X` / `Bộ X` / `Cục X` / `Quốc hội` / `Quân đội X` /
  `Tòa án`
- 국제기관: `Liên Hợp Quốc`, `ASEAN`, `WTO`
- 학교 (대학·초중고 모두): `Đại học X` / `Trường THCS·THPT X` /
  `Học viện X`
- 시설: `Bệnh viện X` / `Sân bay X` / `Ga X` / `Cảng X` / `Cầu X` /
  `Bảo tàng X` / `Thư viện X` / `Chùa X` / `Nhà thờ X` / `Đền X` /
  `Sân vận động X`
- 스포츠: `Hà Nội FC` / `V.League` / `Câu lạc bộ X` (정기 리그 = ORG,
  특정 연도판 = EVT)

### 2.5 KO 핵심 경계 케이스

**KO 는 LOC/ORG 외연을 §2.1 보다 좁게 쓴다.** 공용 축은 인공 시설을 전부 ORG 에
넣지만 KO 는 시설을 아예 안 뽑고, 민간 조직도 안 뽑는다.
그래서 **KO 의 ORG·LOC 숫자는 JA·VI·EN 과 나란히 놓을 수 없다.**

한 줄로: **자연·행정 지리 = `LOC` · 정부·행정·공공·정치 기관 = `ORG` · 그 외 전부
비-entity.** 라벨은 표면형 어원이 아니라 **지시체 종류**로 정한다.

| 규칙 | 판정 | 예시 |
|---|---|---|
| 행정구역·정착지·국가·대륙 | `LOC` | `서울시`, `강남구`, `한국`, `아시아` |
| 자연지명 (산·강·바다·섬·호수·화산) | `LOC` | `한강`, `백두산`, `독도` |
| 주소 (도로명·번지) | `LOC` | `테헤란로152` |
| 지명 표면형 — 대표팀·구단·환유로 쓰여도 | `LOC` | `한국`(대표팀), `아우크스부르크`(도시=구단명) |
| 정부 부처·청·위원회 | `ORG` | `교육부`, `국세청`, `경찰청`, `선거관리위원회` |
| 정당·노동조합·정치조직 | `ORG` | `새누리당`, `민노총` |
| 공공기관·공기업 | `ORG` | `한수원`, `한국전력공사`, `국민연금공단` |
| 국제기구·의회 | `ORG` | `유엔`, `나토`, `국회` |
| 환유 정부건물명 — 아래 allowlist 한정 | `ORG` | `청와대`, `백악관` |
| 인공 시설·venue·건조물 | **비-entity** | `서울역`, `인천공항`, `코엑스`, `서울대학교`, `삼성서울병원`, `잠실야구장`, `한강공원` |
| 교통 구조물 (고속도로·교량·철도노선·항만·터널) | **비-entity** | `경부고속도로`, `인천대교` |
| 민간 회사·기업·은행 | **비-entity** | `삼성전자`, `롯데그룹` |
| 언론·방송·통신사 | **비-entity** | `엠비씨`, `KBS` |
| 스포츠 구단·리그 | **비-entity** | `두산 베어스`, `프리미어리그`, `LPGA` |
| 군·군부대·사령부 | **비-entity** | `한국군`, `오산공군기지` |
| 법원·검찰 | **비-entity** | `대법원`, `수원지법` |
| 종교 조직 | **비-entity** | `구원파` |

**비-entity 시설·구조물 범주 27 종**: `역`·`공항`·`병원`·`대학`·`학교`·`미술관`·`박물관`·`도서관`·`경기장`·`구장`·`공원`·`극장`·`궁`·`빌딩`·`타워`·`터미널`·`센터`·`교회`·`성당`·`전망대`·`휴게소`·`연수원`·`다리`·`고속도로`·`철도노선`·`항`·`터널`

**비-entity 조직 범주 16 종**: `민간`·`회사`·`기업`·`은행`·`언론`·`방송`·`통신사`·`스포츠`·`구단`·`리그`·`군`·`군부대`·`사령부`·`법원`·`검찰`·`종교조직`

**판정을 못 박는 표기는 `` `표면형`=판정 `` 다** — 라벨러 프롬프트도 같은 표기를
쓰고 테스트가 두 쌍 집합을 대조한다. 산문으로만 적으면 문자열은 남기고 판정만
뒤집는 변경이 검사를 지난다.

**범주가 예시보다 앞선다** — 모델이 일반화하는 것은 예시가 아니라 범주라, 위 두
목록이 규칙의 본체이고 표의 예시 칸은 그 사례다. 그래서 이 둘은 라벨러 프롬프트의
같은 열거와 테스트로 묶여 있다.

**운영 조직이 딸린 시설도 예외 없이 비-entity 다** — `서울대학교`·`삼성서울병원` 은
"운영기관을 지칭하면 ORG" 예외를 두지 않는다. 예외를 두면 같은 표면형이 문맥마다
갈려 판정이 다시 열리고, 그 판정은 재라벨을 돌릴 때마다 다르게 나온다.

**환유 정부건물명 allowlist 6 종**: `청와대`·`백악관`·`정부청사`·`국회의사당`(환유로 쓰일 때)·`크렘린`·`펜타곤`.

건물이지만 **특정 정부 조직을 환유**하므로 ORG 로 남긴다 — "청와대는 입장을
밝혔다" 는 정부 행위주체이지 방문 장소가 아니다. 같은 행위주체를 이름 어원
(건물어 vs 조직어)만으로 가르면 오히려 비일관해진다. **열거로 처리하는 것은
"환유인가" 를 매번 판정하면 그 판정이 새 자를 만들기 때문이다** — 목록 밖은
시설이라 비-entity 다. `국회`·`의회` 처럼 조직어 자체는 위 표의 의회 행으로 이미
ORG 라 allowlist 에 넣지 않는다.

**회색지대 판정** — 접미사만으로 안 갈려 문맥으로 정하는 자리:

| 표면형 | 판정 축 |
|---|---|
| `청`/`서` | 정부기관 `청`=`ORG`(`국세청`) / 시설 `서`·`소`=비-entity(`경찰서`·`소방서`) — 아래 접미 판정 마커 |
| `원(院)` | `병원`·`대학원`=비-entity(시설) / `법원`=비-entity(사법기관) / 정부 공공 `연구원`=`ORG` — 이 행이 정하는 것은 **복합 기관명**(`국립과학수사연구원`·`한국항공우주연구원`) 쪽이고 맨 `연구원` 표면형이 아니다 |
| `관(館)` | `박물관`·`미술관`·`도서관`=비-entity(시설) / allowlist 환유 건물명(`백악관`)=`ORG` |
| `공사`/`공단` | `공사`·`공단` 공기업=`ORG`(`한국전력공사`) / 산업단지(`개성공단`)=`LOC` / 민간 항공사·시공사=비-entity |
| `세종대로`류 | 주소 맥락=`LOC` / 교통 간선 맥락=비-entity |

**단독 표면형 3 종**: `정부`=ORG(정부 조직 환유) · `경찰`=비-entity · `군`=비-entity.
뒤 둘은 제복 인력·조직을 가리키며 기관명 `경찰청`·`국방부`만 `ORG` 다.

**접미 판정 3 종**: `청`=ORG · `서`=비-entity · `소`=비-entity.

**시설 접미 예외 2 종**: `경찰서`=비-entity · `소방서`=비-entity. 기관이 아니라
시설이라 그렇다(`청`=`ORG` / `서`·`소`=비-entity — 위 회색지대 표).

**회의체는 비-entity 로 빼기 전에 EVT 후보인지 먼저 본다** — `국무회의`·`기자회견`
처럼 개최되는 회의·회견 사건은 §5.3 R2 로 `EVT` 다. 조직처럼 보인다는 이유로 여기서
바로 빼면 그 자리가 통째로 사라진다.

**복합 지명+시설은 지명만 남긴다** — `서울 명동성당` → `서울명동` `LOC`, 성당은
버린다. 연속된 행정지명 요소(시·구·동)는 붙여서 `LOC` 하나다.

## 3. PROD vs EVT vs ORG 경계 (공통)

- 정기 운영 리그·팀(지속 조직) → `ORG`. **대회·경기·컵은 정기·연차
  개최라도 `EVT`** 다 — 리그는 계속 존재하는 조직이고 대회는 열렸다 끝나는
  사건이라 같은 칸에 들 수 없다(§3.3). 리그의 **특정 연도판**("UEFA
  Champions League 2007-08")도 그 판 자체가 한 번의 대회라 `EVT`
- 음악·영화·책·만화·게임·TV 프로그램 → `PROD`. 단 온라인 운영형 게임·
  방송 플랫폼은 §3.2 로 비-entity, 1회성 방송 행사는 §3.1 로 `EVT` 다
- "Danh sách..." (Wikipedia "List of") 는 entity 아님 → 무시
- 학명 Latin binomial ("Bulbophyllum X") 는 entity 아님 → 무시
- 모델 번호 단독 ("RV522") → `PROD` 아님. 브랜드+모델 결합
  ("Galaxy S24") 만 `PROD`
- 인프라 — 운영주체는 `ORG`(`JR東日本`), 개별 구조물도 `ORG`(역·공항·
  교량·터널), 여러 지점을 잇는 경로는 `LOC`(철도·지하철 노선·도로·
  고속도로). 가르는 기준은 **하나의 구조물인가, 지점들을 잇는 경로인가**
  다. 구조물은 한 자리를 차지하는 시설이라 §2.1 의 ORG 축에 들고, 경로는
  지리를 가로지르는 위치 자체라 LOC 축에 든다 — `東京駅` 은 `ORG`,
  `JR京都線` 은 `LOC` 다. **구조물은 그 자체로 이름을 갖는 시설까지이고,
  그 안의 설비 단위(`N호기`·동)는 시설이 아니라 부분이라 비-entity 다**
  (§3.4). **KO 는 이 항 밖이다** — 교통 구조물(고속도로·교량·철도노선·항만·
  터널)을 운영주체만 빼고 전부 비-entity 로 뺀다(§2.5)
- 약어 단독 (`LKAB`, `IBM`, `JR`, `NHK` 등) → 회사·조직 가능성 우선
  `ORG`. `PROD` 로 분류하려면 명시적 제품 컨텍스트 (브랜드+모델 결합,
  또는 동사 `開発した`/`販売した`/`発売した` 가 직접 수식) 필요
- 동음이의 가타카나 단독 (`タランテラ` = 회사 vs 제품) → 텍스트 내
  동사·수식 문맥으로 판단. `本社`/`会長`/`設立` 등 조직 시그널 →
  `ORG`. `発売`/`新作`/`型番` 등 제품 시그널 → `PROD`. 시그널 부재
  시 `ORG` 우선

### 3.1 PROD 회색지대 4범주 (제조 artifact·법령·전시·프로젝트)

§3 기본 원칙으로 가려지지 않는 PROD 경계 4범주를 명시한다.

| 규칙 | 판정 | 예시 |
|---|---|---|
| 제조 명명 탈것·무기·함정·항공기·우주선·기관차 (형식·급·모델명 결합) | `PROD` | `209型潜水艦`, `IV号戦車`, `四式戦闘機`, `テゲトフ級戦艦`, `イージスシステム`, `スペースシャトルエンデバー`, `ラプターメタンエンジン`, `報国丸級貨客船` |
| 법령·법률·법안·규정·칙유 (법적 문서·제도) | **비-entity** | `証券取引法`, `民法`, `マスキー法`, `平和安全法制`, `軍人勅諭`, `○○法案`, `律令法` |
| 전시·투어·프리미어·1회성 방송 이벤트 | `EVT` | `レモン展`, `UHHA!…TOUR`, `国際プレミア`, `ワールド・エコノ・ムーブ` |
| named 프로젝트·계획·전략·프로그램 (제품개발 코드네임은 §3.3 으로 비-entity) | `EVT` | `Eggsプロジェクト`, `Google Summer of Code Project`, `子育て生活もっとハッピー化計画!`, `石油食料交換プログラム`, `高齢者保健福祉推進10ヵ年戦略` |

보조 원칙:
- **generic vs named**: 형식·고유명 없는 일반명사 단독(`新幹線`·
  `スペースシャトル`·`プロジェクト`)은 비-entity. 형식·급·고유명
  결합(`955形新幹線高速試験電車`)만 해당 타입 — §3 "모델번호 단독 vs
  브랜드+모델" 과 동형. **다만 `東海道新幹線` 처럼 구간을 가리키는 노선명은
  §3 대로 `LOC`** 다 — `新幹線` 이 붙었다고 PROD 가 아니라 그 이름이
  *차량*을 가리킬 때만 PROD 다.
- **番組(작품) vs 방송 이벤트**: 방송 *프로그램* 은 `PROD`(`NHKスペシャル`),
  1회성 방송 행사·방식은 `EVT`. `プレミアム・コレクションDVD-BOX`(제품)은
  `プレミア` 표면이라도 `PROD`.
- **法 표면 ≠ 법령**: `魔法にかけられて`(영화)·`法政大学校歌`(교가)·
  `ホール・エルー法`(공정)은 法 포함이라도 법령이 아니라 이 행 밖이다.
- **조약·랭킹**: 조약 → `EVT`(§1), "List of"·
  베스트리스트 → 비-entity(§3).

### 3.2 PROD 범위 — 서비스·온라인 운영물·기술 표준 제외

PROD 는 **유형 제품·창작 작품·패키지 소프트웨어·형식명 제조물**에
한정한다. 무형 서비스·온라인 운영물·기술 사양은 PROD 가 아니며 아래로
귀속한다.

| 대상 | 귀속 | 예시 |
|---|---|---|
| 통신·SaaS·웹/온라인 매체·금융상품·멤버십·검정·강좌 | 비-entity | `docomo Wi-Fi`, `Skype`, `PRESIDENT Online`, `生活キャッシング`, `ヤマハ音楽能力検定` |
| 온라인 운영형 게임(MMO) | 비-entity | `TERA`, `ウルティマオンライン`, `R2` |
| 기술 표준·규격·포맷·프로토콜·라이선스 | 비-entity | `PDF`, `XML Schema`, `NVMe`, `GNU Free Documentation License` |
| 회사·사업체·레코드 레이블 | `ORG` | `スズキ`, `マッド・ハッター・ラベル` |
| named 계획·프로젝트·전시·레이싱 시리즈 (제품개발 코드네임은 §3.3 으로 비-entity) | `EVT` | `イージス計画`, `社寺参詣曼荼羅`, `フェラーリ・チャレンジ` |
| 상·훈장·작위·규격기·생물 통칭 (훈장·표창·규격기 한정 — 경마·모터스포츠 race 와 시상식은 §3.3 으로 `EVT`) | 비-entity | `銀獅子賞`, `レジオンドヌール勲章`, `国際キログラム原器`, `blue lace flower` |

보조: 番組(정규 방송 프로그램)·패키지 게임은 PROD 유지. 방송 플랫폼·
위성방송 서비스(`モバHO!`)·게임 서비스 플랫폼(`Xbox Live`)은 비-entity.
형식·급·모델명 제조물(`IV号戦車`·`MBSat`)은 PROD(§3.1 제조 명명 탈것 행).

### 3.3 EVT 회색지대 규정 — scope 재정의

§1 EVT(1회성 행사·전쟁·조약·대회)로 가려지지 않는 EVT 경계를 규정한다.

**EVT 포함 (positive 명문화):**

| 군집 | 판정 | 예시 |
|---|---|---|
| 자연재해·대형사고 (지진·태풍·분화·침몰·추락·폭발 사고) | `EVT` | `東日本大震災`, `関東大震災`, `洞爺丸台風`, `チャレンジャー号爆発事故` |
| named 경제·금융·정치 위기 | `EVT` | `世界恐慌`, `リーマンショック`, `アジア通貨危機`, `湾岸危機` |
| **주기적 복합 행사명사** (선거·투표·조사 — 고유명 수식 없어도) | `EVT` | `総選挙`, `市長選挙`, `大統領選挙`, `知事選`, `補欠選挙`, `国民投票`, `国勢調査` |
| 경기·컵·토너먼트·챔피언십·`歌合戦` (1회성/연차 경기 이벤트) | `EVT` | `甲子園`, `UEFAチャンピオンズリーグ`, `日本シリーズ`, `NHK紅白歌合戦`, `天皇賞`(경마) |
| dated bounded 운동·사건·학살 | `EVT` | `五四運動`, `三・一独立運動`, `安保闘争`, `南京大虐殺` |

**EVT 아님:**

| 대상 | 귀속 | 예시 |
|---|---|---|
| 추상 논쟁·쟁점 topic (`〜問題`·`〜論争`) | 비-entity | `靖国神社問題`, `慰安婦問題`, `統帥権干犯問題`, `キプロス問題` |
| 세기 단위 시대구분 (`〜時代`) | **`DAT`**(§1) — EVT 가 아니다. JA·VI 는 원천에 날짜 라벨이 없어 미커버 | `大航海時代`, `ジャーヒリーヤ` / KO gold `조선시대`·`냉전시대` |
| 다년 지속 process·state·사건 (날짜로 못 묶고 연 단위로 이어지는 것) | 비-entity | `冷戦`, `宗教改革`, `産業革命`, `ホロコースト` |
| 무형 서비스·제품개발 코드네임 (§3.2 연장) | 비-entity | `ポストカプセル郵便2001`, `プロジェクト・ミッドウェー` |

**보조 원칙:**

- **운영리그 vs 경기**: 정기 운영 리그·팀(지속 조직)은 `ORG`(`Jリーグ`·
  `メジャーリーグ`·`プレミアリーグ`). 1회성/연차 경기 이벤트(컵·토너먼트·
  챔피언십·`チャンピオンズリーグ`·`甲子園`)는 `EVT`. §3 이 정한 "지속
  조직=ORG / 열렸다 끝나는 사건=EVT" 를 *경기성 명칭*에 적용한 것이다.
- **bounded vs 지속**: 날짜로 묶인 1회성 사건(전투·학살·운동·재해)은 EVT,
  날짜로 못 묶고 연 단위로 이어지는 상태·process·사건(`冷戦`·`革命`·
  `ホロコースト`)은 비-entity. 경계 예: `南京大虐殺`(6주, EVT) vs
  `ホロコースト`(연 단위, 비-entity) — **같은 학살이라도 날짜로 묶이는지가
  가른다.**
- **때를 가리키는 표면형은 `DAT`**: 사건·process 의 이름 *자체* 는 위 표
  대로 EVT 이거나 비-entity 지만, span 의 **머리가 때를 가리키는 말**
  (`시대`·`후`·`시기`·`때`·`년대`·`세기`)이면 §1 의 날짜라 `DAT` 다.
  가르는 것은 지속 연수가 아니라 **머리가 사건을 부르는가 때를 부르는가**
  이며, KO gold 가 `2차 세계대전`(EVT)과 `제2차 세계대전 후`·`냉전시대`
  (DAT)를, EN gold 가 `post-Cold War`(EVT — 머리가 `War`)와 `the early
  post-war years`(DAT — 머리가 `years`)를 그렇게 가른다. 세기 단위
  시대구분(`大航海時代`·`ジャーヒリーヤ`)은 이름 자체가 때라 파생 없이도
  `DAT` 이며, 그래서 위 표의 다년 지속 행과 겹치지 않는다.
  **EVT 가 아니라고 곧 비-entity 는 아니라는 뜻이다.** 원천이 날짜 라벨을
  주지 않는 JA·VI 에서는 이 자리가 모두 미커버로 남는다.
  **명절·기념일·절기 이름은 `EVT` 다** — 달력의 특정한 하루를 부르는
  고유명이라 머리가 때여도 이름 쪽이 이긴다(`설날`·`추석`·`크리스마스`·
  `한글날`·`빼빼로 데이`·`동지`·`입춘`). 그 이름에 머리가 하나 더 붙으면
  **그 머리가 무엇을 부르는지**로 갈린다 — 여전히 그 하루를 부르면 `EVT`
  이고(`크리스마스날`·`크리스마스 이브`·`새해 첫날`), 그 하루가 아니라
  둘레의 기간·범위를 부르면 `DAT` 다(`크리스마스 시즌`·`설 연휴`·
  `크리스마스때`·`초딩 크리스마스 시절`). 앞에 회차·날짜·상대 수식이
  붙어도 머리는 안 바뀌므로 `EVT` 다(`8.15 광복절`·`2월 설`). 이름이
  아니라 범주를 부르는 말(`명절`·`공휴일`)은 고유명이 아니라 `DAT` 다.
  **하루가 아니라 구간을 부르는 이름도 `EVT` 다** — §5.3 이 열거한
  `새해`·`신년`·`연말연시`·`라마단` 넷이고, **이것은 원칙이 아니라 닫힌
  목록이다.** 하루 이름과 달리 구간 이름은 형태로도 뜻으로도 `연말`·`올해`
  와 안 갈린다 — `연말`(年末)과 `연말연시`(年末年始)가 똑같이 굳은 한자
  합성어라 "한 낱말인가" 로도 못 가르고, 둘 다 해의 한 구간을 가리켜
  "가리킴인가" 로도 못 가른다. §5.3 이 `회`·`식` 을 `어휘경계` 로 뺀 것과
  같은 처지라 원칙을 세우는 대신 목록을 적고, 목록 밖 구간 표현은 `DAT` 다
  (`연말`·`올해`·`지난해`·`한 해`). 넓히려면 §5.3 을 고쳐야 한다.
  이름 쪽은 뒤에 무엇이 붙어도(`새해 예산안`·`새해 인사말`) 그 이름 자리가
  `EVT` 이며, 붙은 말이 기간 머리일 때만 더 긴 `DAT` 한 덩어리가 된다.
  범주어(`명절`·`공휴일`)가 따라오는 자리는 자동으로 갈리지 않는다 — 그것이
  머리일 수도(`작년 설 명절`) 서술일 수도(`한글날 공휴일 되찾기`) 있어
  사람이 자리마다 본다.
  **머리 판정은 span 밖의 뒤따르는 말까지 본다** — gold 의 경계가 같은
  표현에서 갈려(`추석 연휴` 한 span ↔ `추석` 만 달고 `연휴` 는 무라벨),
  앞엣것만 `EVT` 로 옮기면 경계 차이가 타입 차이로 바뀐다. 이름 뒤에 기간
  머리가 바로 붙거나 **등위로 그 머리를 나눠 갖는**(`설과 추석 연휴`·
  `설, 추석, 휴가철 때`) 자리는 그 자리의 옳은 span 이 더 긴 `DAT` 한
  덩어리이므로 `DAT` 로 둔다. 등위까지 보는 것은 바로 뒤만 보면 뒤 접속항만
  걸러져 **한 명사구 안에서 타입이 갈리기** 때문이다. 경계 자체의 교정은
  축3 소관이다.
  **어느 어근이 명절 이름인지는 §5.3 이 열거한다** — 형태만으로는 `설날`
  과 `이날` 을 못 가르기 때문이다(gold 의 `날` 머리 `DAT` 는 `이날`·
  `전날`·`다음날` 이 압도한다). §5.3 이 `회`·`식` 을 `어휘경계` 로 뺀 것과
  같은 이유이며, 개방집합이라 완전성은 회수로 보강한다.
  **이 판정은 KO 전용이다** — EN gold 는 `New Year` 를 `EVT` 로 달고
  `Christmas` 는 둘로 갈리는데 재라벨이 없어 원천을 그대로 두고, JA·VI 는
  `DAT` 이 PII 합성 주입분이라 이 자리가 미커버로 남는다.
- **주기적 복합 행사명사 예외**: §3.1 "generic 단독=비-entity" 의 예외 —
  `総選挙`·`国勢調査` 등 제도화된 주기적 공식 행사를 지시하는 복합 사건
  명사는 고유명 수식이 없어도 EVT(1회성 행사 지시). 단, 단일 generic
  사건명사(`戦争`·`地震`·`祭`·`大会` 단독)는 named/수식 시에만 EVT.
- **賞 명칭**: 경마·모터스포츠 races(`天皇賞`·`グランプリ`)·시상**식**
  (`授賞式`·`Awards`)은 EVT. §3.2 "상·훈장·규격 → 비-entity"는
  훈장·표창·규격기 한정(시상 행사 아님).

### 3.4 KO PROD 경계 — eponymy·명명 탈것·SW·span 범위·설비 호기

§3.1~§3.3(JA 이식분: 운영리그·법령·시대구분)으로 가려지지 않는 **KO 고유
모호 케이스**를 아래로 닫는다. KLUE 사람 gold 의 PER/LOC/ORG/DAT 도
silver(경계·타입 noise 존재)이며 본 규칙은 전 타입에 적용된다 — PROD 만
상세표를 받는 것은 나머지가 무오류라서가 아니다.

| 류 | 규칙 | 예시 |
|---|---|---|
| **eponymy** (작품명↔인물·배역) | "이 영화/드라마/노래/작품"으로 치환되면 `PROD`, "이 사람/배우/감독/배역"이면 `PER`. 단서: 봤다·개봉·명작·OST→PROD / 출연·연기·役→PER | `동주`(영화)=PROD / `동주`(役)=PER, `미이라`·`드라큐라`·`스탠바이미`·`오로라공주` |
| **명명 탈것·무기·함정·항공기** | 탈것 *자체* = `PROD`(§3.1 과 정합). **단독 표면형은 PROD** — 명시적 사건 head(`…참사`·`…침몰 사고`·`…폭발 사고`)가 붙을 때만 `EVT` | `세월호`=PROD / `세월호 참사`=EVT, `칼라시니코프`·`S-300` |
| **패키지 SW·동음이의** | 시판/패키지 SW·OS·named 프로그램 = `PROD`(§3.2). 회사·지명 동음이의는 문맥 시그널로 분기 | `알파고`(바둑 프로그램)=PROD, `신세계`=ORG(회사)·LOC(지명)·PROD(영화) |
| **span 범위**(boundary) | 고유명 *핵심* 까지만. 영숫자 모델·버전 designator 는 포함(`S-300`·`SM5`·`아이폰5`), 일반 분류·형식·편성 명사는 제외(`소총`·`공중미사일방어시스템`·`극장판`·`시리즈`·`시즌 N`) | `칼라시니코프 소총`→`칼라시니코프`, `스킨스시즌 1`→`스킨스` |
| **발전 설비·호기** (원자로·발전소 unit) | **비-entity** — §3 인프라(노선=LOC/운영주체=ORG) 연장, *설비 단위*는 개체명 아님 | `고리 1호기`·`한빛 3호기` |

보조 원칙:
- **eponymy 치환 테스트가 1순위**: 같은 표면형이 문맥별로 PROD/PER 갈린다
  (분류기는 문맥으로 학습). 작품이 인물·배역명에서 유래해도 *작품을 지시*하면
  PROD, *사람·배역을 지시*하면 PER.
- **명명 탈것은 표면-literal**: §3.3 의 자연재해·named 사고(EVT)와 구분 —
  사고를 가리키는 *사건 head*(참사·침몰 사고·폭발 사고)가 명시될 때만 EVT,
  탈것 이름 단독은 PROD(JA 의 탈것=PROD / 사고=EVT 분리와 동형).
- **span 범위는 §3 "브랜드+모델 결합만 PROD" 와 동형**: 영숫자 designator
  (`S-300`·`SM5`)는 고유명 일부라 포함, 한국어 일반 분류명사(`소총`·`시스템`)
  는 제외. gold 의 긴쪽/짧은쪽 혼재를 짧은쪽(핵심)으로 통일.
- **설비 호기는 비-entity**: 발전소·원자로 unit(`N호기`)은 §3 인프라(노선=LOC/
  운영주체=ORG)의 연장으로 *설비 단위* — PROD 아님.
- **기존 gold 에 소급 적용하지 않는다**: 이 절의 규칙은 코퍼스 재생성 시
  반영한다 (§5.3 축3 "기존 gold 는 소급 트림하지 않는다" 와 같다).

**EN 은 원천이 넘치는 유일한 언어다.** JA·VI·KO 는 원천이 빈약해 LLM 재라벨로
부족한 타입을 만들어냈지만, OntoNotes5 는 사람이 붙인 18 종이라
`PRODUCT`·`WORK_OF_ART`·`EVENT` 가 이미 있다. 그래서 재라벨이 없고, 대신
18 종 중 9 종을 버린다 — 위험이 "없는 것을 지어내다 틀리는" 쪽이 아니라
**"있는 것을 버리다 잃는" 쪽**이다. 그 위험은 매핑표 전수성 게이트와 타입별
span 카운트 고정이 막는다.

`DAT` 은 주입하지 않는다 — 원본 `DATE` 가 gold 로 주기 때문이며 KO 가 KLUE 에서
날짜를 받는 것과 같은 구조다. PII 는 미국 단일 체계다(`en` 은 언어지 국가가
아니라 US·UK·AU 가 전화·ID 체계를 달리 쓴다).

**수식 위치 GPE 는 빼지 않는다.** `U.S. troops` 의 `U.S.` 는 §2.3 의
"국적·소속 수식 명사구 → 비-LOC" 에 걸리지 않는다. §2.3 이 배제하는 것은
**지명에 접미가 붙은 파생어**(`日本人`·`アメリカ製`)이고 지명 자체가 수식
자리에 온 것은 다르다. `アメリカ大統領` 은 일본어에서 한 단어라 하위 span 이
생기지 않으므로 **§2.3 은 영어의 이 경우를 결정하지 않는다** — 결정하려면 새
규정이 필요하고 이 절은 그것을 만들지 않는다.
