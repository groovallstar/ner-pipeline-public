# 코딩 컨벤션

이 프로젝트의 공통 코딩 규칙. 모든 신규 코드 및 수정에 적용.

## 주석 / 문서 언어 정책

| 위치 | 언어 |
|------|------|
| `print()` / `logger.*` 출력 메시지 | **영문** |
| Exception 메시지 | **영문** |
| 함수·메서드 docstring | **한국어** |
| 클래스 docstring | **한국어** |
| 모듈 상단 docstring (스크립트 헤더) | **한국어** |
| 인라인 코드 주석 (`#`) | **한국어** |
| CLI `--help` (argparse `description`, `help`) | **영문** |

### 이유

- 로그/예외/CLI는 외부 도구(grep, monitoring, 외부 라이브러리 traceback)와 섞이므로 ASCII로 유지.
- 주석/docstring은 팀 내부 문서이므로 한국어로 의도와 맥락을 명확히.

### 예시

```python
"""한국어 NER 라벨링 결과를 평가한다.

벤치마크 입력은 KLUE 데이터셋이며, span F1과 seqeval 메트릭을 함께 계산한다.
"""

def compute_f1(gold: List[str], pred: List[str]) -> float:
    """gold/pred 태그 시퀀스의 F1 점수를 계산한다."""
    if not gold:
        raise ValueError("gold tags are empty")  # 예외는 영문
    logger.info("Computing F1 over %d samples", len(gold))  # 로그는 영문
    # 빈 태그는 'O'로 정규화한다  ← 인라인 주석은 한국어
    ...
```

## 코드·주석에 변경 이력 표기 금지

코드 본문, 주석, docstring, 로그·예외 메시지, 변수·함수·파일 이름에 변경 이력을
설명하기 위한 GitHub Issue 번호(`#42`, `issue-42`), PR 번호, 날짜(`2026-05-04`),
작성자 표기, "방금 고친 버그" 류 일시적 맥락을 남기지 않는다.
기능 구현이나 테스트 데이터에 필요한 날짜·사람 이름은 이 금지 대상에 포함하지 않는다.

### 이유

- 코드는 머지 후에도 수년간 살아남지만 이슈·PR·날짜는 회수되거나 의미가 바뀐다 — 주석이 거짓말을 시작한다.
- 영구 보관이 필요한 맥락은 아래 채널이 이미 존재한다:
  - **왜 이렇게 됐는가**: 커밋 메시지 본문 + `refs #N`
  - **언제·누가**: `git blame` / `git log`
  - **설계·검증 히스토리**: `docs/issues/issue-{N}-{slug}.md`
  - **자유 형식 실험 기록**: `docs/reports/`
- 코드에 박힌 이슈 번호는 grep 결과를 오염시키고, 리네이밍·아카이브 후 dead link가 된다.

### 금지 예시

```python
# ❌ 이슈 번호 박제
def load_dataset():  # issue #40 에서 추가
    ...

# ❌ 날짜 박제
# 2026-05-04: PII 라벨 영문화 후 재학습
LABELS = [...]

# ❌ 일시적 맥락
# TODO(승현): 다음 스프린트에 제거
legacy_path = ...
```

### 허용 예시

```python
def load_dataset():
    """canonical 10종 평면 BIO 시퀀스를 JSONL에서 읽는다."""
    ...

# WikiANN의 LOC는 GPE를 포함하므로 LOC로 정규화한다  ← WHY만 남김
LABELS = [...]
```

장기 마커가 필요한 미해결 작업은 GitHub Issue로 분리하고 코드에는 이슈 번호 없이 의미만 남긴다.

## docstring·주석의 참조 무결성

docstring·인라인 주석·모듈 헤더는 **실재하는 대상만** 가리킨다. 존재하지
않거나 이름이 바뀐 파일·경로·데이터셋·CLI 플래그, 이미 폐기된 계획·측정
방식을 참조로 남기지 않는다. 코드가 참조 대상을 바꾸면(파일 삭제·rename,
기능 구현·폐기, 플래그 추가·제거) 그것을 가리키는 docstring·주석을 **같은
커밋에서** 동기화한다.

참조가 **실재하는데 서술만 틀린** 경우도 같다. 상수·기본값·필드 목록·동작을
바꾸면 그것을 *설명하는* 문장이 함께 낡는데, 이름은 그대로라 grep 에도 안
걸리고 링크도 안 깨져 오래 살아남는다. 무엇을 바꿨든 그 이름을 언급하는
docstring·주석·문서를 찾아 **서술까지** 맞춘다.

### 이유

- 죽은 참조는 grep·문서 탐색을 오염시키고, 폐기된 계획이 docstring에 남으면
  나중에 그대로 되살릴 유혹(attractive nuisance)이 된다.
- 틀린 서술은 존재 검사로 안 걸린다 — 이름이 살아 있고 문장만 거짓이라
  코드를 열어 대조해야 드러나고, 그때까지 읽는 사람을 계속 오도한다.
- 검증이 여러 모듈에서 반복 적발한 재발 결함이다 — 파일 rename·기능 구현
  후 그것을 가리키던 docstring만 stale 로 남는 사례.

### 예시

```python
# ❌ 존재하지 않는/이름 바뀐 대상 참조
def build_eval():
    """pii_all.jsonl 을 읽어 평가셋을 만든다."""  # 파일은 rename 됐음
    load(CLEANED_PATH)

# ❌ 폐기된 계획·없는 플래그를 docstring 에 존속
"""측정은 A->B->C 3지점으로 완성한다(`--mode seq`)."""  # 계획 폐기·플래그 없음

# ❌ 이름은 실재하는데 서술이 코드와 모순
"""seed 는 비교 가능성 판정에 쓰지 않는다."""  # seed 가 판정 필드에 추가됨

# ✅ 참조 대상과 동기화
def build_eval():
    """정제된 gold(CLEANED_PATH)를 읽어 평가셋을 만든다."""
    load(CLEANED_PATH)
```

## 문서 수치는 산출 파일에서 그대로 옮긴다

문서·리포트·커밋 메시지의 수치는 **산출 파일 값을 그대로** 적는다. 차이·비율
같은 파생값을 문서에서 다시 계산하지 않는다 — 이미 반올림된 값끼리 빼면
오차가 눌어붙어 같은 사실이 문서마다 다른 숫자로 갈린다. 파생값이 필요하면
산출 단계에서 계산해 파일에 담는다.

행 수·건수·support 처럼 **데이터가 바뀌면 낡는 수치**는 어느 파일 기준인지
함께 적는다. 범위·상한을 쓸 때는 실측 최댓값이 그 안에 들어가는지 확인한다.

### 이유

- 표·산문의 수치는 자동으로 검증된다고 가정하지 않는다. 인용한 값과 원본
  산출물의 일치를 확인한다.
- 검증이 여러 작업에서 반복 적발한 재발 결함이다 — 반올림 연쇄, 데이터
  재생성 뒤 낡은 행 수, 실측이 상한을 넘는 범위 표기.

## 인용 수치의 산출 경로를 남긴다

영구 문서가 인용하는 수치는 **그것을 만든 코드까지** 커밋한다. metric JSON
만 보관하고 산출 스크립트가 untracked 면 숫자는 남아도 어떻게 나왔는지
되짚을 수 없다. 산출물 보관만으로 재현 가능성이 보장되지는 않는다.

이미 인용된 산출물은 **덮어쓰지 않는다.** 같은 경로에 재생성하면 문서가
가리키던 값이 조용히 다른 값으로 바뀌고 옛 수치는 산문에만 남아 근거를
잃는다. 재측정은 새 경로로 낸다.

### 이유

- 재현 불가능한 게이트 수치는 게이트 구실을 못 한다 — 뒤에 오는 사람이
  같은 기준으로 다시 잴 방법이 없다.
- 검증이 반복 적발했다 — 산출 스크립트 부재, untracked 하네스, 재생성으로
  canonical 이 산문에만 남은 사례.

## 같은 규칙의 사본은 함께 고친다

한 규칙이 여러 사본으로 존재할 때(프롬프트의 단건·배치·시스템 변종 등)
규칙을 고치면 **모든 사본을 같은 커밋에서** 고친다. few-shot 예시도 규칙의
일부다 — 규칙 문장만 옮기고 예시를 한쪽에 두면 변종마다 다른 출력이 나온다.

"두 구현이 같은 템플릿을 쓴다" 같은 서술은 **쓰기 전에 실제로 같은지
확인한다.** 사본이 갈라진 뒤에도 이 문장이 남으면 한쪽만 고쳐도 된다는
잘못된 믿음을 준다.

### 이유

- 사본 간 비대칭은 어느 변종이 실행됐느냐에 따라 다른 결과를 내는데, 그
  선택이 로그에 안 남으면 원인 추적이 어렵다.
- 검증이 반복 적발했다 — 규칙 문장을 한쪽 변종에만 추가, few-shot 예시 누락.
