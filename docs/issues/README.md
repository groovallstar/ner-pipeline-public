# docs/issues/ — 이슈 문서 보관소

GitHub Issues의 계획·결과 스냅샷을 누적 보관하는 디렉토리다. 실시간 협의·승인 기록은 GitHub Issue 본문·댓글이 **단일 출처(single source of truth)**이고, 이 디렉토리는 기능 설계·구현 히스토리를 **영구 보존**하는 용도로만 쓴다.

운영 전반 규칙은 프로젝트 루트 `CLAUDE.md` → "이슈 관리" 섹션 참조.

## 디렉토리 구조

```
docs/issues/
├── README.md                                # 이 파일 (규칙·템플릿)
└── issue-{번호}-{슬러그}.md                  # 이슈별 계획+구현 통합 문서
```

- `{번호}`: GitHub Issue 번호 (gh가 부여한 자동 채번 값)
- `{슬러그}`: kebab-case 영문 요약 — 브랜치 슬러그와 동일하게 맞춘다. 예) `vi-crawler`, `ja-pii-verify`, `span-evaluator-fix`
- 파일은 이슈별 **단일 .md**로 관리한다. 계획과 구현 결과를 한 파일 안에 상하로 배치하고, 디렉토리·하위 파일은 만들지 않는다.
- **파일명에는 날짜를 넣지 않는다.** 이슈 번호가 영구 식별자이고, 머지·종결 시점은 GitHub Issue/PR 메타데이터와 git 이력에 남는다. 시점 정보가 필요하면 본문 상단의 `승인일`·`완료일` 필드와, 메트릭이 환경(모델/데이터 버전)에 의존할 경우 검증 섹션에 측정일을 기재한다.

## 작성·커밋 시점

| 단계 | 동작 | 커밋 여부 |
|---|---|---|
| 3단계 (계획 승인 직후) | 계획 섹션을 로컬에 기록 | **커밋하지 않음** |
| 4단계 (구현 중) | 필요 시 계획 섹션 수정 | 커밋하지 않음 |
| 5단계 (PR 직전) | 구현 결과·검증·관련 커밋 섹션 추가 작성 | 계획→구현 양쪽이 정상 작성됐는지 확인 후 **이때 최초 커밋** |

- 이슈 문서는 "계획 단계"에서는 커밋하지 않고 사용자가 로컬에서 직접 읽어가며 진행한다.
- 구현이 끝난 뒤 같은 파일에 결과 섹션을 추가하고, 전체 흐름이 정합적인지 검토한 뒤 한 번에 커밋한다.
- 계획이 크게 바뀌어 이미 커밋된 이슈 문서를 수정해야 하면 `docs(issues):` 접두사로 후속 커밋(`refs #N`)을 남긴다.

## 이슈 md 템플릿

```markdown
# issue-{N}: {제목}

- Issue: https://github.com/groovallstar/ner_pipeline/issues/{N}
- PR: (머지 직전 채움)
- 브랜치: `feat/issue-{N}-{슬러그}`
- 승인일: YYYY-MM-DD
- 완료일: YYYY-MM-DD  <!-- 5단계에서 채움 -->

## 목적
<!-- 왜 이 작업이 필요한가 -->

## 범위
- 포함:
- 제외:

## 성공 기준
- [ ] 테스트:
- [ ] 문서 갱신:
- [ ] 메트릭/검증:

## 구현 단계 (3~6)
- [ ] 1.
- [ ] 2.
- [ ] 3.

## 위험·의존성
<!-- 외부 서비스, 데이터, 백엔드 가용성 등 -->

---

<!-- 이하 섹션은 5단계(PR 직전)에서 추가 작성 -->

## 변경 요약
<!-- 무엇을 어떻게 바꿨는가 — 3~5줄 -->

## 구현 결과 (계획 대비)
- [x] 1. ... (완료)
- [x] 2. ... (완료)
- [ ] 3. ... (보류·이월 시 사유 명시)

## 검증
- 테스트: 명령어 / 결과 (pass·fail, 관련 파일)
- 메트릭(해당 시): F1 / latency / throughput — 변경 전후 비교
- 리뷰어 확인 사항:

## 관련 커밋
- `<hash>`:
- `<hash>`:

## 후속 작업·알려진 한계
<!-- 분리된 이슈 번호 또는 TODO -->
```

## 주의

- `docs/issues/`는 **보관용**이다. 구현 전략이 변하면 Issue 쪽을 먼저 갱신하고, 머지 직전에 이슈 md에 최신 내용을 반영한 뒤 커밋한다.
- 타 `docs/` 폴더와 역할이 겹치지 않게 한다. 이 폴더는 **이슈별 히스토리**만 담고, 도메인 지식·실행 가이드·엔티티 스펙 등은 해당 폴더에 맡긴다. 전체 구조는 루트 `CLAUDE.md`의 디렉토리 트리 참조.
