# README를 현재 프로젝트 구성과 실행 방법에 맞게 갱신

## 배경·목표

README의 실행 명령과 데이터 준비 과정 설명을 현재 구현에 맞추고,
처음 사용하는 사람이 설치 조건과 모델 준비 방법, 관련 문서를 찾을 수 있게 한다.

## 범위·제약

- README의 소개, 파이프라인, 설치, 서버 실행, 검증 및 문서 안내를 갱신한다.
- 제품 코드, 데이터, 모델과 상세 매뉴얼은 변경하지 않는다.
- 기존 이슈 #297의 미커밋 코드·테스트·기록을 보존하고 이번 변경에 포함하지 않는다.
- 커밋·푸시·PR 생성은 수행하지 않는다.

## 완료 기준

- 실행 명령과 서버 설정 설명이 코드 및 매뉴얼과 일치한다.
- 삭제된 일회성 데이터 준비 도구와 현재 제공하는 기능을 구분한다.
- README의 상대 링크와 CLI 도움말, diff 공백 검사를 확인한다.
- 최종 변경에 대한 Superpowers 리뷰를 수행하고 지적을 처리한다.

## 현재 상태

- 이슈: https://github.com/groovallstar/ner-pipeline/issues/298
- 작업 브랜치: `feat/issue-298-readme-refresh`
- 분기 기준·향후 PR 대상: `origin/develop`·`develop`
- 원격 develop을 fetch한 뒤 로컬 develop·기존 HEAD와 모두 차이가 없음을 확인했다.
- README 갱신과 문서 검증·리뷰를 완료했으며 통합 게시 요청에 따라
  커밋·푸시·초안 PR 게시를 진행한다. 원격 게시 결과는 이슈에 연결한다.

## 결정 이력

- 상세 스키마와 운영 설정은 중복하지 않고 기존 매뉴얼로 연결한다.
- 기존 작업과 분리된 브랜치를 같은 작업 공간에서 만들었다. 기존 미커밋 변경은
  작업 트리에 그대로 보존하며 이번 작업의 리뷰 대상에서 제외한다.

## 결과·검증

- 설치·서버 실행 명령을 `uv` 기준으로 통일하고, 모델 배치·API 호출 예시와
  언어 감지 한계, 현재 도구와 코퍼스 생성 이력의 구분을 보완했다.
- `uv run python -m server --help`: 종료 코드 0. 문서에 사용한
  `--model-root`, `--host`, `--port` 옵션을 확인했다.
- `uv run python`으로 README를 읽어 상대 링크 19개의 존재와 코드 펜스 짝을
  검사했다. 모두 통과했다.
- README의 bash 블록 5개를 `bash -n`으로 검사하고, curl 요청 본문 2개를
  `server.app.NERRequest.model_validate`로 검증했다. 모두 통과했다.
  최초 검사 스크립트는 잘못된 `server.schemas` import 때문에 실행에 실패했으며,
  실제 정의 위치인 `server.app`으로 수정한 뒤 다시 실행했다. 제품 결함은 아니었다.
- `git diff --check`: 종료 코드 0.
- Superpowers `requesting-code-review` 절차의 읽기 전용 리뷰 서브에이전트가
  README 최종 diff와 이 작업 문서를 검토했다. Critical·Important·Minor 지적이
  모두 없었으며, 결과 기록 권고를 반영했다. 리뷰에서 제외한 기존 이슈 #297,
  실모델 실행, 커밋·푸시는 이번 작업 범위 밖이라는 판단을 유지했다.
- 완료 기준을 모두 충족했다. 실행 명령·설정은 코드와 대조하고 CLI 도움말을
  실행했으며, 삭제된 도구를 구분하고 상대 링크·예제·공백 검사와 리뷰를 마쳤다.
- 제품 코드 변경이 없어 전체 pytest·ruff 검사는 실행하지 않았다.
- 실제 모델 추론과 GPU·외부 LLM 호출은 문서 변경의 검증 범위에 포함하지 않는다.

## 통합 게시 결정

- 사용자 요청에 따라 이슈 297의 F1 입력 검증, README 갱신, 검증 로그 보존
  지침과 규약 문서 이동을 한 PR로 게시한다. 기존의 분리·미게시 결정은
  이번 통합 게시 요청으로 변경되었으며 과거 기록은 위에 유지한다.
- 브랜치는 `feat/issue-298-readme-refresh`, PR 대상은 `develop`이다.
  게시 전 fetch 결과 HEAD와 `origin/develop`은
  `2ca5b701fc92b8183823f86884fd51417935d896`으로 동일하다.
- 규약 문서는 내용 변경 없이 `docs/manual/specs/`로 이동했으며 루트·문서·
  보고서 지침과 프롬프트 테스트의 참조를 함께 갱신한다.
- 일반 검증의 콘솔 출력은 별도 파일로 남기지 않고, 실험·벤치마크·데이터
  변환 결과는 보존한다. 사용자가 요청한 경우에만 예외를 적용한다.
- README 자체의 이전 리뷰 결과는 재사용하고, 통합 게시 과정에서 추가된
  지침·경로·기록 변경은 독립 리뷰로 확인한다.

## 통합 게시 전 최종 검증

- README 상대 링크 19개, bash 예제 5개(`bash -n`), 요청 JSON 2개
  (`server.app.NERRequest.model_validate`), 코드 펜스 짝과
  `uv run python -m server --help`를 다시 확인했고 모두 통과했다.
- 두 작업 문서의 상대 링크 존재와 규약 문서의 내용 변경 없는 이동을 확인했다.
  `uv run ruff check`와 `git diff --check`도 통과했다.
- 추가 코드 변경을 포함한 전체 검증 결과와 기존 실모델 실패의 분리 근거는
  [F1 입력 검증 작업 기록](issue-297-eval-sentence-count.md)의
  통합 게시 전 최종 검증에 남긴다. 전체 통과로 보고하지 않으며 초안 PR로 게시한다.

- 통합 게시의 Superpowers 독립 리뷰는 기존 승인된 구현·README·로그 정책의
  리뷰 결과를 재사용하고, 규약 이동·참조·테스트 간격·최종 기록을 검토했다.
  Critical·Important·Minor 지적은 없으며 기존 실모델 실패 때문에 병합 준비
  완료가 아닌 초안 PR 게시로 판정했다. 테스트를 대신한 리뷰로 취급하지 않는다.
