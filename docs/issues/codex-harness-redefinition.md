# Codex 하네스 재정의: 단계별 로드맵과 현황

- 조사일: 2026-09-08.
- 기준 브랜치: `ner-pipe-codex`.
- 상태: 하네스 정비 후 사용자 요청에 따라 로컬 Claude 설정과 certified 원장·전용 검사를 정리했다. 관련 검사 통과를 확인한 뒤 docs/superpowers 이관 문서와 전용 검사도 제거했다. 기존 EN 배포 지문 불일치와 실모델·GPU·외부 backend 미검증 범위가 남아 있다. 구현·검증 기록은 이 문서에, 커밋·푸시 결과는 Git 이력과 완료 보고에 남긴다.
- 목적: 현재 지침과 실행 도구를 기준으로 필요한 하네스를 점진적으로 정비한다.
- 10단계는 정비 프로젝트의 순서다. 모든 개발 작업에 10단계 절차를 강제하지 않는다.
- 이 문서는 현황·결정·적용 기록이다. 실제 실행 지침은 수정된 AGENTS.md를 따른다.

## 10단계 로드맵

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 현재 지침·도구·검증 체계와 공백을 조사한다. | 구성도, 충돌·공백, 유지·정리·보강 분류와 남은 불확실성을 정리한다. |
| 2 | 목표·적용 범위·성공 기준을 합의한다. | 프로젝트 전용과 전역 공통 범위, 필수·조건부·제외 항목을 정한다. |
| 3 | 지침의 책임과 지식 탐색 구조를 설계한다. | 전역 지침, 프로젝트·하위 AGENTS, 스킬, 운영 도구의 소유 범위와 충돌 해소안을 정한다. |
| 4 | 요구사항·자율 판단·변경 기록 방식을 설계한다. | 질문할 정책과 직접 판단할 선택, 대체된 결정의 기록 위치를 정한다. |
| 5 | 기존 Docker 운영 지침을 참조하고 구현 결함을 후속 이슈로 분리한다. | 지침의 소유 위치와 후속 이슈를 연결한다. 서버 도구 수정은 이번 하네스 정비에서 제외한다. |
| 6 | 대표 사용자 흐름의 검증 방식을 설계한다. | 요구 기능, 대상 서버, 기대 결과와 성공·실패·미검증 판정을 정한다. |
| 7 | 기존 완료 전 리뷰 정책의 누락·실패·중복 처리를 확인한다. | 전역 정책과 적용 기록을 대조한다. 새 리뷰 범위·템플릿·도메인 검토 절차는 추가하지 않는다. |
| 8 | 승인된 최소 설계를 구현한다. | 필요한 지침과 기존 도구만 수정하고 변경에 맞는 검증을 통과한다. |
| 9 | 대표 작업으로 실제 효과를 검증한다. | 정상 동작뿐 아니라 잘못된 설정·대상·누락을 검출하고 개입 부담을 평가한다. |
| 10 | 채택·운영·유지보수 기준을 확정한다. | 효과 없는 장치를 제외하고 사용법, 소유 범위, 되돌리는 방법을 남긴다. |

2~7단계는 하나의 설계를 점진적으로 구체화한다. 단계마다 별도 플러그인이나 문서를 만들지 않는다. 비용이 효용보다 크면 항목을 축소하거나 제외한다.

사용자 후속 지시에 따라 각 단계와 세부 항목은 조사→필요한 결정→수정→검증까지 처리한 뒤 넘어간다. 기존 지침의 명확한 오류는 8단계까지 미루지 않는다. 새 실행 도구처럼 후속 설계가 필요한 구현은 의존성을 명시하고 해당 단계에서 완결한다. 단순히 목록에 적었다는 이유로 해결 완료로 처리하지 않는다.

## 기록을 읽는 기준

아래 초기 조사와 사용자 검토 절은 당시 상태와 결정 이력이다. 현재 리뷰
정책은 「후속 결정: 플러그인에 종속되지 않는 완료 전 리뷰」와 루트 AGENTS.md를
따른다. 최신 조사·분류는 「1단계 잔여 조사」를 따른다. 과거 reviewer 역할의
표시·호출 기록을 현재 세션의 도구 가용성으로 해석하지 않는다.

### 실행과 검증 도구

- [서버 지침](../../src/server/AGENTS.md)은 API·PII·동시성 계약과 테스트 명령을 제공한다. `--help` 검사는 실행 옵션 배선을 확인하지만 실제 사용자 흐름의 성공 증거는 아니다.
- [배포 지침](../../docker/server/AGENTS.md)은 모델 준비 상태와 번역 backend 명시를 요구한다.
- [기동 스크립트](../../docker/server/start.sh)와 [Compose 설정](../../docker/server/docker-compose.yml)은 프로젝트명·컨테이너명·포트를 변수로 받는다. worktree마다 세 값을 함께 분리하거나 실행 대상의 출처를 확인하는 보장은 확인되지 않았다.
- [실서버 테스트](../../tests/server/test_live_server.py)는 임시 포트에 프로세스를 띄우고 health·단건 NER·잘못된 언어 요청을 검사한다. 번역까지 연결한 흐름은 이 파일에서 검사하지 않는다. 서버 출력을 버리므로 기동 실패 진단 근거도 제한된다.
- [이관 테스트](../../tests/migration/test_codex_migration.py)는 지침 이전과 의도적 미도입 결정을 검사한다. 실제 기능의 종단 간 성공을 대신하지 않는다.
- `.github`에서 확인한 파일은 이슈 템플릿 두 개다. 저장소 내 GitHub Actions workflow는 확인되지 않았으며 외부 CI의 존재 여부는 조사하지 않았다.
- 이번 단계에서는 테스트·서버·GPU·외부 서비스·훅을 실행하지 않았다. 정적 조사 결과를 동작 검증 성공으로 해석하지 않는다.

### 과거 자료를 적용하는 경계

[기존 활성화 기록](https://github.com/groovallstar/ner-pipeline/blob/b564d5e02402ba09fb8bc3babbecdc0e945326bf/docs/superpowers/specs/codex-activation-checklist.md)은 과거 이관 당시의 결과다. 당시 사용자 훅을 추가하지 않았다는 사실은 현재 훅이 없다는 뜻이 아니다.

복구된 `feat/english-rest-api`의 마지막 커밋에는 설계 기록이 남아 있다. 이후 미커밋 구현 로그와 비교 문서는 삭제되어 이번 조사에서 원문을 다시 읽지 못했다. 번역 비활성 환경 제공, 불필요한 질문, 요구 정책 변경 설명에 관한 관찰은 앞선 대화의 분석에서 가져온 후보 근거이며 현재 브랜치의 재현 결과가 아니다. 영어 기능 복원은 이번 하네스 정비 범위에 자동으로 포함되지 않는다.

## 설계 방향 후보

- 권장 방향은 프로젝트 지침의 작은 정리와 기존 실행·검증 도구의 보강이다. 현재 확인한 문제에 직접 대응하고 유지보수 면적을 제한할 수 있다.
- 지침만 보강하는 방향은 도입 비용이 낮지만 실행 설정 누락을 기억과 판단에 계속 의존한다.
- 새 통합 플러그인·오케스트레이터를 만드는 방향은 여러 저장소에서 반복되는 요구가 확인된 뒤 검토한다. 현재 근거로는 기존 Superpowers·Orca와 책임이 중복될 가능성이 크다.

## 다음 단계

2단계에서는 프로젝트 내부 도구와 지침을 우선 정비하는 범위를 기준으로, 전역 공통화가 필요한 항목을 선별하고 검증 가능한 성공 기준을 정한다. 현재 구성의 삭제·재설치, 전역 설정 변경, 새 훅 설치는 이 현황 조사에서 수행하지 않았다.

참고한 원칙은 [OpenAI 하네스 엔지니어링](https://openai.com/ko-KR/index/harness-engineering/)의 짧은 지침과 탐색 가능한 지식, 직접 실행·관찰 가능한 환경, 중요한 불변 조건의 검증이다. 구체적인 요구사항과 우선순위는 이 저장소의 조사 결과에서 도출한 제안이다.

## 1단계 세부 진행: 지침의 중복과 충돌

### 조사 범위와 상태

저장소 AGENTS.md 16개 전체, 사용자 전역 지침, 세션에 제공된 프로젝트 지침을 읽었다. Superpowers의 brainstorming·requesting-code-review 및 리뷰 템플릿·verification-before-completion을 대조하고 TDD·worktree 스킬의 관련 조건을 확인했다. 모든 스킬이나 프로젝트 구현 전체의 정합성을 검증한 것은 아니다.

첫 항목의 문서 간 책임·충돌 분류를 완료했다. 다음 항목인 실제 적용 경로 검증, 기존 도구 재사용성, 검증 공백, 절차 비용, 장치 소유 범위는 아직 남아 있다. 1단계 전체를 완료한 것으로 처리하지 않는다.

### 분류 결과

| ID | 관찰 | 분류와 권장 처리 |
|---|---|---|
| A1 | 브랜치 루트는 reviewer 출력을 Findings·Verification gaps·Verdict로 고정한다. 설치된 스킬 템플릿은 Strengths·Issues·Recommendations·Assessment를 사용한다. 세션의 사용자 지침은 템플릿 중복 정의를 금지한다. | 정리 후보. 사용자 지침을 우선하고 프로젝트는 리뷰 대상 계약과 읽기 전용 책임을 남기며 출력 템플릿의 중복 소유를 없애는 방향을 검토한다. |
| A2 | 브랜치 루트의 리뷰 입력은 git diff HEAD다. 이것만으로는 이미 커밋한 작업 변경과 미추적 파일 내용을 포함하지 못한다. 스킬의 커밋 범위만 사용하면 반대로 미커밋 변경을 놓친다. | 보강 후보. 작업 시작 기준부터 현재 결과까지 실제 리뷰 대상이 누락되지 않도록 입력 범위를 정해야 한다. 단순히 한 템플릿을 다른 템플릿으로 바꾸는 것으로 끝내지 않는다. |
| A3 | 루트는 native code-reviewer 또는 generic fallback을 지시하고 세션 사용자 지침은 프로젝트 reviewer를 지정한다. 설치 스킬은 general-purpose를 예시로 사용한다. | 정리 후보. 현재 제공되는 역할과 상위 지침에 맞게 역할을 선택하고 런타임별 이름을 여러 문서에 고정하지 않는다. 실제 호출 가능성은 다음 항목에서 확인한다. |

### 이번 항목의 결정

## 1단계 세부 진행: 실제 적용 경로

### 확인 결과

- 현재 호스트 CLI는 `codex-cli 0.153.4`다. 이 버전 확인은 현재 대화 런타임의 내부 버전까지 증명하지 않는다.
- 전역 설정에서 플러그인 기능과 Superpowers 활성 설정을 확인했다. 현재 세션에는 Superpowers 스킬 목록이 제공되어 있으며 관련 SKILL.md를 실제로 읽었다. 모든 스킬이 매번 자동 실행되거나 지침 준수가 강제된다는 의미는 아니다.
- 전역 AGENTS.md와 현재 브랜치 루트 파일의 내용, 현재 세션에 직접 제공된 사용자 지침을 구분했다. 모든 하위 AGENTS.md가 매 세션 자동 주입되는지는 이번 검사로 입증하지 않았다. 파일의 존재·수동 읽기와 자동 로딩은 별개다.
- 현재 도구 설명에는 reviewer 역할이 있지만, 실제 `agent_type=reviewer` 호출은 `agent type is currently not available`로 실패했다. 따라서 역할 표시만으로 실행 가능하다고 판정하지 않는다.
- `agent_type=default`로 범용 검토자를 호출한 결과, 지침 A1/A2의 루트 파일 근거를 읽고 한정된 검토 결과를 반환했다. 전체 대화는 전달하지 않고 파일 경로와 검토 범위를 지정했다. 범용 fallback 호출은 검증되었지만 읽기 전용 권한의 기계적 차단은 검증하지 않았다.
- Orca 훅 8종의 등록, 대상 스크립트의 읽기·실행 가능 상태와 endpoint·port·token·pane 환경변수의 존재를 확인했다. 비밀값은 출력하거나 문서에 저장하지 않았다.
- endpoint 기술 파일은 읽기 가능하지만 해당 위치에 spool 디렉터리와 현재 pane 기록은 없었다. spool 부재는 전달 성공 또는 훅 미실행 중 어느 쪽도 증명하지 않는다. 수신측 기록 확인이나 합성 이벤트 전송은 하지 않았으며 실제 전달 성공은 미검증이다.

## 사용자 검토 후 정정

- 리뷰 형식은 별도로 지정하지 않는다는 사용자 지시에 따라 루트에서 스킬 템플릿에 관한 언급 자체를 제거했다. 기존 고정 출력 형식도 다시 추가하지 않는다. 관련 정적 검사에서 해당 문구 요구를 제거했다.
- 사용자는 커밋 완료 시점에 리뷰하는 의도를 설명했다. 리뷰 시점과 비교 범위를 구분하여 논의 중이며 커밋 전후 흐름을 새로 변경하지 않았다.
- reviewer 대체 경로와 반복 승인 관련 문장은 추가 설명 후 판단할 항목이다. 기존 수정이 사용자에게 확정 승인된 것으로 처리하지 않는다.
- 실제 포트·CLI 검증 범위, 서비스와 학습 지원 범위·과거 기록 구분, 검증 결과 설명은 사용자가 수용했다.

- 후속 사용자 확인에 따라 반복 승인 관련 문장을 루트에서 제거했다. 이 원칙은 상위 지침으로 유지되며 프로젝트에 중복하지 않는다.
- 리뷰를 별도 에이전트에게 맡기는 방향은 사용자가 확인했다. 커밋 후 비교 범위의 필요성도 이해했으나, 기존 Claude 리뷰 방식의 변경 요구가 있어 구체적인 리뷰 절차는 당시 확정하지 않았다. 후속 결정은 아래 완료 전 리뷰 절을 따른다.


## 후속 결정: 플러그인에 종속되지 않는 완료 전 리뷰

사용자는 리뷰를 작업 완료 절차에 필수로 포함하도록 결정했다. 최종 변경의
리뷰가 완료되어 있으면 그 결과를 사용하고, 완료되지 않았으면 에이전트가
Codex CLI의 `codex review`를 실행한다. 지침은 특정 플러그인을 언급하지 않는다.
커밋 전후는 고정하지 않고 대상에 맞는 기본 옵션을 사용한다. 프로젝트에서
검토 범위·출력 템플릿·도메인 검토 항목을 별도로 정의하지 않는다.
이는 과거의 프로젝트 reviewer 및 변경 전체 전달 계약을 대체한다.
기존 Claude 자산과 과거 이관 기록은 보존한다. 리뷰 외 워크플로의 플러그인
의존성 정리는 이번 결정에 포함하지 않는다.

수락 기준은 완료 전 리뷰 의무, 기존 리뷰의 중복 호출 방지, 리뷰 부재 시
CLI 실행, 기본 리뷰 절차 사용, 지적 수정 후 검증·재검토, 실행 불가 시
미완료 보고다. 기존 migration 정적 계약 검사를 갱신하여 확인한다.
런타임과 데이터 스키마 변경이 없으므로 구현 맵과 스키마 문서의 갱신은 불필요하다.

## 2단계: 목표·범위·성공 기준

### 배경과 목표

Claude Code와 OMC에서 Codex와 다른 플러그인으로 전환할 때, 저장소의 필수
절차가 특정 역할 이름·스킬·훅·상태 파일에 결합되어 운영 계약도 함께 바뀌었다.
이번 정비의 목표는 저장소가 필요한 작업·검증·리뷰·완료 기준을 소유하고,
플러그인의 설치 여부와 무관하게 기본 도구로 그 기준을 수행할 수 있게 하는 것이다.
플러그인이 이미 수행한 검증과 리뷰는 근거가 현재 변경에 유효하면 재사용한다.
플러그인 삭제·재설치는 성공 조건이 아니다.

사용자가 이미 확정한 정책은 완료 전 리뷰 필수, 리뷰 미완료 시 에이전트의
`codex review` 실행, 완료된 리뷰 중복 호출 방지, 리뷰 기능의 기본 범위·형식
사용, 별도 도메인 리뷰 제외다. 이 항목은 다시 승인받을 대상이 아니다.

### 적용 범위

사용자가 전역 Codex 지침 변경을 함께 진행하도록 결정했다. 공통 검증·리뷰
절차는 사용자 전역 지침에, NER 계약과 구체적인 명령·자원 규칙은 저장소에 둔다.
전역 config.toml, 플러그인 설치·훅 등록 변경은 이번 지침 정리의 대상이 아니다.

출력·작업 문서를 재사용한다. 2단계 완료는 이 목표와 범위를 정한 상태를 뜻하며,

전역 규칙이 없는 다른 사용자 환경까지 이번 변경으로 구성되지는 않는다.

현재 세션은 파일을 직접 읽어 적용하며, 파일 수정이 이미 실행 중인 모든
세션의 시스템 지침을 다시 로드한다고 주장하지 않는다.

### 검증과 복구 경계

전역 파일의 변경 전 사본은 저장소 밖 임시 디렉터리에 보관했다. 이 파일은
저장소 Git 커밋에 포함되지 않으므로 저장소 revert만으로 전역 변경이 복구되지
않는다. 복구할 때는 현재 전역 파일의 후속 변경을 먼저 확인하고 이번에 추가한
공통 검증·리뷰 절만 제거하거나 보관한 사본과 대조한다.

정적 계약 테스트는 수정 전 2 failed / 44 passed로 새 위임 계약이 없음을
확인했다. 수정 후 테스트·전역 문구 검사·리뷰 결과는 완료 보고에서 명시한다.
검토자가 전역 변경을 놓치지 않도록 변경 전후 사본과 diff 경로를 전달한다.


## 4단계: 요구사항·자율 판단·변경 기록

### 배경과 적용 원칙

명확한 요청에 같은 승인을 반복하거나, 구현 편의를 위해 요구 기능을 축소한
뒤 완료로 보고하는 일을 막는 것이 목적이다. 현재 대화에서 승인한 방향과
전역 작업 지침의 자율 진행 원칙을 명문화하며, 새 승인 파일이나 플러그인
전용 상태를 만들지 않는다.

### 책임과 기록 위치

- 전역 AGENTS.md에는 요구사항 확인, 승인된 범위의 자율 진행, 질문할 조건,
  결정 변경 시 남길 내용을 추가했다. 요청의 취소·대체 없이 원래 목표를 버리지
  않는 원칙과 질문에 의존하지 않는 작업의 계속 진행을 포함했다.
- 저장소 루트는 [Codex 작업 기록](README.md#codex-작업-기록)으로 연결한다.
  공용 README는 GitHub Issue 기반 작업과 승인된 spec 기반 작업을 모두 다룬다.
  기존 spec을 재사용하고 별도 원장·계획서·반복 승인 절차를 추가하지 않는다.
- GitHub Issue와 로컬 문서의 연결은 유지하되, 대화에서 확정한 결정의 반영 여부를
  구분한다. 원격 기록 갱신을 위해 사용자 승인 없이 댓글이나 메시지를 보내지 않는다.
- 이번 하네스 정비의 현재 작업 기록은 이 문서다. 과거 이관 spec은 역사 기록으로
  보존한다. 전역 정책과 프로젝트 정책의 정본은 각각 해당 AGENTS.md다.

### 발견한 연결 누락과 수정

- `docs/manual/rest-api-spec.md`의 검증 절은 전체 서버 테스트를 모델 없이
  실행할 수 있는 검사처럼 설명하고 있었다. 6단계에서 분리한 기본·전체·live
  검사의 자원 조건과 번역 흐름 선택을 반영하고 서버 지침과 번역 테스트 맵에
  연결했다. 기존 예제에 부하 검사가 포함된다는 점도 명시했다.
- `docker/server/AGENTS.md`의 전체 pytest 명령에 skip 사유 출력을 추가하고,
  기본·전체 검사의 자원 조건은 서버 지침을 참조하도록 연결했다.
- 서비스 API·설정·번역 구현, Docker lifecycle 스크립트, pyproject.toml과
  uv.lock은 HEAD 대비 변경이 없음을 확인했다. 새 실행 도구·의존성·플러그인·훅은
  추가하지 않았다. canonical 스키마와 certified 원장은 이번 변경 대상이 아니다.

### 검증과 의존성

이번 단계는 문서 연결만 수정한다. 7단계 최종 CLI 리뷰에서 확인한 모델 없는
서버 테스트 155 passed / NLLB 3 skipped, migration 46 passed와 코드 검토 결과를
재사용한다. 테스트와 서비스 구현에 새 변경이 없으므로 실모델·GPU·Docker를
추가 실행하지 않는다. 문서의 대상 링크·현재 명령·diff를 확인하고 변경한 최종
문서는 기본 `codex review --uncommitted`로 검토한다.

미커밋 변경과 신규 작업 기록은 여전히 현재 worktree에 있다. 사용자 전역
AGENTS는 저장소 밖에 있으므로 저장소 Git만으로 다른 사용자 환경에 배포되거나
복구되지 않는다. 코드 통합에 남은 신규 구현 의존성은 발견하지 못했으며,
실모델 자원 검증과 #259·#260은 위에서 구분한 조건부·후속 범위로 남긴다.


## 9단계: 대표 작업의 효과와 개입 부담 평가

### 평가 대상과 추가 실행

6단계의 live 검사 보강과 NER→번역 연결, 7·8단계의 리뷰 실패 처리 및 문서
통합을 대표 작업으로 사용했다. 별도 제품 기능이나 모델 품질 실험을 만들지
않았다. 유효한 회귀·뮤테이션·리뷰 결과를 재사용하고 아래 두 조건만 추가 실행했다.

- 임시 빈 모델 루트를 `NER_SERVER_MODEL_ROOT`로 지정하고, 상위 환경에는
  `NER_SERVER_TEST_NLLB_MODEL=deliberately-unavailable-model`과
  `NER_SERVER_TEST_LIVE_TRANSLATE=1`을 넣었다. 그 환경에서 서버 지침의
  모델 없는 기본 명령을 그대로 실행했다. 명령의 `env -u`가 NLLB 실모델
  활성화 변수를 해제하고 live·모델 통합 파일을 제외하여 155 passed / 3 skipped였다.
- 같은 빈 모델 루트에서 `uv run pytest tests/server/test_live_server.py -q -rs`를
  실행했다. ja·vi·ko 모델 경로 누락을 명시하며 번역 2개를 포함한 5개 모두
  skip되었다. 이것은 pytest 선택과 사전 조건의 동작 검증이며 실서버 성공이 아니다.
- 환경은 자식 프로세스에만 전달했고 임시 디렉터리는 제거했다. 서비스 기동,
  모델 다운로드·GPU 할당·외부 backend 호출은 수행하지 않았다. 임시 실행 로그는
  `/tmp/ner-stage9-basic.log`와 `/tmp/ner-stage9-missing-models.log`에 있다.

### 사용자 개입과 절차 비용

- 5단계의 서버 운영 설계 확대는 사용자의 지적으로 범위를 조정했다. 이후
  #259·#260 등록과 분리는 명시적 요청대로 처리했다. 이 사례를 에이전트가
  처음부터 적절한 최소 범위를 선택한 성공으로 평가하지 않는다.
- 승인 후의 6단계 테스트 보강, 실패 원인 확인, 문서 연결 수정은 세부 구현
  선택마다 재승인을 요구하지 않고 진행했다. 번역 회계값을 HTTP 응답에
  가정한 테스트 오류는 계약을 바꾸지 않고 테스트를 바로잡았다.
- 단계별 진행 요청과 완료 보고는 범위를 확인하는 데 도움이 되지만 대화 왕복이
  발생했다. 문서만 바뀐 7·8단계도 `--uncommitted` 기본 범위에 앞선 코드 변경이
  함께 포함되어 리뷰 읽기와 일부 검사 실행이 반복되었다. 새 기록에 대한 리뷰는
  필요했지만 전체 비용이 제거된 것은 아니다.
- 사용자 만족도, 개입 시간과 전환 전후 총비용은 측정하지 않았다. 따라서
  개입 부담이나 처리 시간이 정량적으로 개선되었다고 주장하지 않는다.
- 10단계에서는 이미 정한 유효한 결과 재사용 원칙과 일반 작업에 10단계 절차를
  강제하지 않는 원칙을 유지한다. 이 평가를 근거로 완료 전 리뷰를 생략하거나
  새로운 자동 승인·상태 파일을 추가하지 않는다.

### 판정과 남은 검증

이번 대표 작업에서 정상 동작, 준비성·설정·누락에 대한 실패 검출과 진단
개선은 확인했다. 증거의 범위와 skip을 구분하는 보고도 수행했다. 효과는 이
저장소의 관찰한 작업에 한정되며 모든 새 Codex 세션의 자동 준수나 커밋 차단을
보장하지 않는다. 실모델·GPU·외부 backend·브라우저 UI, Docker 후속 이슈와
리뷰 지적 수정 후 재검토의 실제 경로는 미검증 또는 후속 작업으로 남긴다.

코드는 변경하지 않았다. 8단계의 대상 테스트 95개·Ruff·diff 및 CLI 리뷰 근거를
재사용하고, 이번 두 실행 결과와 기록 변경의 diff를 확인한다. 최종 기록은 기본
CLI 리뷰로 검토하며 채택·유지보수·되돌리기 기준은 10단계에서 정리한다.


## 10단계: 채택·운영·유지보수와 복구 기준

### 채택한 구성과 소유 위치

새 플러그인·오케스트레이터·커밋 훅·승인 파일·리뷰 상태 파일은 채택하지
않았다. worktree별 서버 소유 추적과 기본값 제거도 추가하지 않았다. 당시에는 기존
Claude 자산과 과거 이관 기록을 보존했으나, 아래 후속 사용자 결정이 로컬 설정
보존 정책을 대체한다. 과거 이관 기록은 계속 보존한다.
이 구성은 이미 승인한 결정의 정리이며 새로운 전역 설정 변경을 포함하지 않는다.

### 일상 작업에서 사용하는 방법

1. 해당 작업의 루트·하위 지침과 기존 이슈/spec를 읽고 요구사항·검증 수단을
   식별한다. 이미 승인한 선택을 반복 승인받거나 이 문서의 10단계를 재실행하지 않는다.
2. 변경에 직접 관련된 검사를 실행한다. 서버의 기본·전체·번역 live 선택은
   [서버 검증 지침](../../src/server/AGENTS.md#검증)을 따른다. 실모델·GPU·외부
   backend가 필요한 경우 자원과 설정을 확인하고 실행하지 못한 부분은 미검증으로 남긴다.
3. 현재 변경에 유효한 검증·리뷰 근거를 재사용한다. 최종 변경의 리뷰가 없으면
   전역 정책에 따라 기본 Codex 리뷰를 실행하고, 실제 검토 완료 출력까지 확인한다.
4. 결과와 한계를 보고한다. 명령 실행 실패, 검사에서 발견한 결함, skip·제외를
   구분하고 커밋·배포 여부를 작업 완료와 별도로 명시한다.

이 순서는 기존 지침의 사용 안내다. 별도 체크리스트 제출이나 단계별 승인
절차를 만들지 않는다. 9단계에서 관찰한 대화 왕복과 리뷰 반복 비용을 일반
작업에 강제하지 않으며, 사용자에게 필요한 상태 보고와 유효한 결과 재사용을 유지한다.

### 유지보수 기준

- 새 테스트가 실모델·네트워크·서버 기동을 요구하면 기본 명령의 제외·활성화
  조건도 함께 점검한다. 현재 두 파일 제외 목록이 미래의 모든 자원 의존
  테스트까지 자동으로 보호한다고 가정하지 않는다.
- 설정·API·준비성 계약을 바꿀 때 기존 회귀 검사와 매뉴얼을 함께 갱신한다.
  실패 검출을 약화시키거나 skip으로 바꿔 통과시키지 않는다.

루트 지침·README·리포트 안내·매뉴얼은 원장 승격 의무를 제거하고 원본 출처와
실행 조건을 명시하는 원칙을 유지하도록 갱신했다. 과거 metric 수치는 변경하지
않았으며 현재 설명에서 필요한 과거 원장 근거는 삭제 전 Git 링크로 연결했다.
이관 문서 제거 후 다시 검사하고 최종 리뷰하며, 잔존 EN 환경 불일치와 자원
의존 경로를 별도로 보고한다.

이관 문서 제거 후 동일 범위는 361 passed / 11 skipped / 9 warnings였다.
3개는 NLLB 실모델, 8개는 KO gold 부재 skip이며, 별도 경고로 생략한 gold
대조도 실검증으로 계산하지 않는다. 변경·신규 Python 파일 전체의 Ruff와
`git diff --check`를 통과했다. 소스 두 파일의 문서 수정은 docstring을 제외한
AST가 HEAD와 같음을 확인했다. tests·src에서 certified 및 docs/superpowers
직접 경로 참조는 남아 있지 않다. EN 패키지의 기존 지문 실패는 위 별도 결과에
그대로 남으며, 전체 테스트가 모두 통과했다고 보고하지 않는다.


## 커밋·푸시 요청

사용자가 현재 worktree의 변경 전체를 커밋하고 푸시하도록 요청했다. 최종 정비
결과를 함께 검토하여 `ner-pipe-codex` 브랜치에 커밋하고 같은 이름의 원격
브랜치로 푸시한다. 앞선 절의 미커밋 표기는 각 단계 실행 당시의 상태 기록이다.
기존 EN 배포 지문 불일치와 미검증 자원 경로는 해결된 것으로 바꾸지 않는다.
`codex-dotfiles`는 이미 별도 private 저장소의 main에 푸시되어 있고, 초기화한
위키 submodule의 추적 커밋은 변경하지 않았다. 캐시·임시 실행 기록은 커밋에
포함하지 않는다.
