## 3. 성능 개선 방법

### 3.1 프롬프트 튜닝 (v1 → v3, +4.3%p)

에러 분석 기반으로 3라운드에 걸쳐 프롬프트를 정제함:

**라운드 1 (v2): 엔티티 경계 명확화**
- 施設名 예시 추가: 연구소, 도서관, 미술관, 병원, 점포
- 法人名 예시 추가: 철도 회사 ("○○鉄道" = 法人名, 施設名 아님)
- 製品名 예시 추가: 소프트웨어, 제품, TV 프로그램
- イベント名 vs その他の組織名 구분 명확화: 스포츠 리그(ラ・リーガ, Jリーグ)는 조직이지 이벤트가 아님
- 결과: イベント名 +9.8%p, 施設名 +8.9%p

**라운드 2 (v3): 군사/정부 조직 규칙 추가**
- 에러 분석 결과 군사 조직(米軍, ソ連軍, 第57狙撃師団)이 その他の組織名으로 오분류됨
- 규칙 추가: "○○軍", "○○師団", "○○旅団" = 政治的組織名
- 규칙 추가: "○○庁", "○○省", "○○院" = 政治的組織名
- 결과: 政治的組織名 +12.7%p (0.70 → 0.82)

**라운드 3 (v4): 학습 데이터 기반 Few-shot**
- Stockmark 학습 데이터(1,600+건)에서 혼동 사례를 자동 마이닝
- 짧고 대비 효과가 높은 예시를 선별하여 프롬프트에 추가:
  - "北海道東海大学"(法人名) vs "旭川キャンパス"(施設名) 동일 문장
  - "藤岡高校"(施設名) vs "高崎鉄道管理局"(政治的組織名) vs "大映スターズ"(その他の組織名)
  - "神栖郵便局"(施設名) vs "茨城県神栖市"(地名)
- 결과: 전체 엔티티에서 precision 추가 향상

### 3.2 Span Matcher 개선 (v4, +1~2%p)

기존 `span_matcher.py`는 정확한 부분 문자열 매칭만 수행. 두 가지 폴백 추가:

**공백 정규화:**
- 문제: LLM이 "1983 年"(공백 포함)으로 출력하지만 원본 텍스트는 "1983年"(공백 없음)
- 수정: 내부 공백을 제거한 후 재매칭 시도
- 효과: 기존 매칭 실패 span의 약 5%를 복구

**조사/접미사 제거:**
- 문제: LLM이 조사(は/が/を)나 경칭(氏/さん)을 포함하여 출력
- 수정: 일반적인 일본어 조사 및 접미사를 제거한 후 재매칭 시도
- 효과: 소폭이지만 일관된 개선

### 3.3 Two-Pass 검증 (+1~2%p precision)

1차 엔티티 추출 후, 2차 LLM 호출로 각 엔티티를 검증:
- 1차: 일반적인 엔티티 추출
- 2차: 원문 + 추출된 엔티티를 제시하고 "이 엔티티가 맞는지" 확인 요청
- 검증을 통과한 엔티티만 최종 결과로 채택

**효과:**
- Precision 크게 향상 (예: 27B에서 0.80 → 0.85)
- Recall 소폭 하락 (일부 정답 엔티티도 필터링됨)
- 순 F1 개선: +1~2%p
- 트레이드오프: 추론 시간 2배 증가

### 3.4 Self-Consistency 투표 (테스트 완료, 미채택)

다수결 투표 방식 테스트:
- 3회 반복 추론, 2회 이상 등장한 엔티티만 채택
- 결과: 개선 없음 (F1 0.798 → 0.794)
- 원인: 모델 출력이 이미 일관적이어서, 투표가 오히려 맞는 경계 사례를 제거함
- 결론: 최종 파이프라인에 미포함

## 4. 토큰화 문제

### 일본어: 띄어쓰기 없는 토큰화

일본어는 단어 경계가 없어 BIO(토큰 단위) 태깅이 비실용적:
- `sentence.split()`이 전체 문장을 하나의 토큰으로 처리
- 예: "鉄道事業は既に名古屋鉄道がほぼ統合していた" → 1 토큰
- **해결:** BIO/seqeval 대신 문자 오프셋 기반 span-level 평가 사용

### 한국어: 음절 단위 불일치

KLUE NER은 음절 단위 어노테이션을 사용하지만, LLM은 어절 단위 span을 출력:
- Gold: "서 울 시" (3개 음절 토큰, B-LC I-LC I-LC)
- LLM: "서울시" (1개 span)
- LLM span을 음절 단위 BIO 태그로 변환 시 정렬 오류 발생
- **영향:** 네이티브 BIO 모델 대비 ~10-15%p F1 페널티
- **해결:** Span-level 평가(문자 오프셋)가 LLM 비교에 더 공정

### LLM 고유의 span 문제

| 문제 | 예시 | 영향 | 해결 |
|------|------|------|------|
| 공백 삽입 | "1983 年" vs "1983年" | span 매칭 실패 | 공백 정규화 |
| 조사 포함 | "東京で" vs "東京" | 오프셋 불일치 | 조사 제거 |
| 범위 불일치 | "イオン上田店" vs gold "上田店" | 부분 일치 = 실패 | 조사 진행 중 |
| 복합명 분리 | "トップチャレンジリーグ豊田自動織機シャトルズ"를 2개로 분리 | span 불일치 | 프롬프트에 "복합명은 분리하지 말 것" 추가 |

## 6. 재현 방법

### 일본어 NER 벤치마크

```bash
# 기본 벤치마크
PYTHONPATH=src python -m evaluators --lang ja \
    --models "vllm:Qwen/Qwen3.5-27B" \
    --max-samples 200 \
    --vllm-url "http://localhost:8081/v1" \
    --concurrency 8 \
    --output results/ja_benchmark.json

# Two-pass 검증 포함 (enhanced_labeler)
PYTHONPATH=src python3 -c "
from labelers.ja.vllm_ner_labeler import VllmNERLabeler
from labelers.ja.enhanced_labeler import EnhancedLabeler
base = VllmNERLabeler(base_url='http://localhost:8081/v1', model='Qwen/Qwen3.5-27B')
labeler = EnhancedLabeler(base, two_pass=True)
spans = labeler.label_spans('텍스트 입력')
"
```

## 7. 향후 계획

1. **Fine-tuning:** Stockmark 학습 데이터(~1,600 샘플)로 Qwen3.5-27B QLoRA fine-tuning. F1 +5~10%p 기대.
2. **한국어 프롬프트 튜닝:** 일본어와 동일한 방법론(에러 분석 → 프롬프트 반복 개선)을 한국어 파이프라인에 적용.
3. **범위 불일치 해결:** 복합명 분리 및 부분 일치 처리 방법 조사.
4. **대규모 테스트:** Stockmark 전체 테스트셋(~400 샘플)으로 보다 안정적인 지표 확보.
5. **언어 간 비교:** 한국어 vs 일본어 파이프라인 아키텍처 차이 분석.
