# ko

## Purpose
Korean NER labelers aligned to the canonical schema with the NER 5 types (PER=person, LOC=location, ORG=organization, PROD=product/work, EVT=event) plus DAT=date. PER/DAT are renamed from KLUE (PS/DT) with KLUE's TI/QT dropped and still follow KLUE NER guidelines (particle exclusion, syllable boundaries, compound merging).

**LOC/ORG do NOT follow KLUE guidelines — they follow the narrow-ORG redefinition.** `ORG` covers government/administrative/public/political bodies only (ministries, agencies, commissions, parties, labor unions, state enterprises, international bodies, legislatures, plus metonymic government-building names). Man-made facilities and venues (stations, airports, hospitals, universities, stadiums, museums) and non-governmental organizations (private companies, broadcasters/press, sports clubs and leagues, military units, courts/prosecution, religious bodies) are **not extracted at all** (non-entity). `LOC` likewise covers only administrative divisions, natural place names, and addresses — building and facility names are dropped. Single source for this rubric: `docs/manual/data/canonical-entity-schema.md` §2.5.

Consequently **KO's LOC/ORG extension differs from JA·VI** — JA·VI canonical absorbs every man-made facility into ORG, while KO discards those same facilities. Do not compare ORG numbers across languages without accounting for this.

PROD/EVT: continuously operating leagues and clubs ("프리미어리그", "메이저리그") are private sports organizations, so they are non-entity rather than ORG; only a specific edition of a competition or a specific match is EVT. Laws, era labels, multi-year states/processes (냉전, 산업혁명), and abstract disputes are non-entity too. The PII types remain unfilled (later increments).

The rules live in **one template** — `SINGLE_PROMPT_TEMPLATE` (vLLM, few-shot). A second copy in OpenAI chat format (`SYSTEM_PROMPT` + `USER_PROMPT_TEMPLATE`) was removed: the OpenAI path was never actually run, yet every rule change had to be written twice, and the two copies had already drifted apart with no check to catch it. The prompt is also **length-bounded** — `tests/ner/labelers/test_prompt_token_budget.py` fails once the fixed instruction outgrows the server context budget, because prompt + reserved output tokens over `max-model-len` makes vLLM reject every request with a 400 that looks like poor model quality in the report.

| `ko_evt_r2_audit.py` | EVT gold audit against the canonical §5.3 rules + R2 recovery (CLI: audit\|judge\|apply\|homomorph\|head-candidates). `audit` is a **re-runnable machine gate** — it reports the R2 coverage rate and rule violations and exits non-zero via `--gate-rate`/`--gate-violations`, so the same command verifies gold before and after a recovery. `judge` asks two independent LLMs per occurrence and keeps only unanimous verdicts; `apply` inserts them and fixes deterministic violations, asserting the other nine types stay byte-identical. `head-candidates` scans gold with the canonical R2 head list — **model predictions are never an input**, because a candidate pool drawn from model FPs grows gold only where the model already fired, which guarantees a recall gain by construction. `homomorph` is the issue #201 consistency gate: every head-homomorph surface with no gold EVT history must be recovered, excluded by a canonical reason code, or judged NOT — it exits non-zero on anything left unclassified |
| `ko_evt_axis1_audit.py` | Axis-1 compound (`proper noun + event head`) head enumeration and site scan (CLI: head-survey\|sites\|codes\|gate\|fp-blindspot\|residue\|apply). `head-survey` **does not let the author pick the candidate set** — it aggregates **every** eojeol inside gold EVT spans (not just the span-final one: `마라톤` sits mid-span in `보스턴 마라톤 대회 폭발 사건` and is invisible to a final-eojeol count, and `폭발`·`붕괴`·`화재` fall below the threshold the same way), keeps those appearing at least `--min-count` times that are standalone corpus nouns with **no proper-noun label history** — that last filter drops the modifier half of the same span (`보스턴`) while keeping the head — and attaches corpus evidence (homomorph types, gold EVT history, other-type labels, whether a shorter candidate already covers it) so canonical can assign an adopt/exclude reason code to *every* candidate. A low EVT-history ratio is ambiguous by construction — it means either a lexical-boundary leak (`분위기` under `위기`) or bulk under-recovery (`교통사고` under `사고`) — so the homomorph list is reported alongside the ratio and a human reads it. `sites` enumerates candidate **sites** (row, span) for a given head list: the proper noun may sit inside the word (`서울월드컵`) or in the preceding eojeol, and a preceding proper noun carrying a particle is rejected (`파리에서 테러` is a sentence constituent, not a compound). Overlap with existing gold EVT spans is measured (`exact`/`inside_longer`/`partial`/`none`), never silently dropped, so absorption stays distinguishable from recovery. The report also cross-tabulates `attachment` × `proper_basis` so the "relax adjacency" follow-up has a committed baseline instead of re-running the scan for every comparison. Its report fingerprints both the head list and the gold file, so a changed population says *which* input moved. `codes` is the reason-code ledger — enumeration is reproducible but **assignment is human**, which is where selection bias could live, so every candidate must carry a canonical code and `--gate` exits non-zero on any left unassigned. `parse_canonical_axis1()` reads **four** population parameters from §5.3 (head list, proper-noun label set, length/ratio guards, reason-code names) and tests compare it against the module constants — the rest of §5.3 is prose this module enforces in code and does not parse: the rule lives in the locked ruler file while this enforcing module does not, so narrowing a head — or quietly moving one from adopted to excluded, which the ledger gate alone would pass — fails the sync test. If §5.3 goes missing, gets renamed, or loses its table, the parser raises instead of returning an empty rule set — an empty parse is indistinguishable from an empty rule, and `canonical_rule_sha256()` would fingerprint the nothing as a normal value. It also stops at the next sibling heading, so a future `### 5.4` cannot leak its rows into the KO population. `gate` is the main consistency gate and it counts **sites, not surfaces** — the same surface gets different verdicts in different rows (`세월호 사고` is an event in one row and part of a committee name in another), so folding by surface lets one row's honest verdict absolve another. Every site must land in one of five buckets — recovered · canonical-excluded · judged NOT · absorbed by a longer gold EVT · type-clash-recorded — and anything left over exits non-zero. The type-clash bucket exists so a site whose head is already covered by a non-EVT gold span has an exit other than "write NOT in the ledger"; without it the only way to green the gate is a forced verdict, and a human judgement that can only go one way is a formality. Recovery count is reported alongside, because if every site is excluded or absorbed then **zero recoveries also passes every check** — a near-zero count is itself a signal to re-examine. The insert span implements the canonical axis-3 boundary clause: a labeled adjacent proper noun is never swallowed (the span is trimmed to the head), and if the head itself is covered the site is a clash rather than an insertion. `apply` inserts the ledger's EVT verdicts and requires **the ledger and the current rule to agree on the boundary** — the site is rescanned, matched by its detection span, and a ledger row whose insert span no longer matches is counted and refused rather than inserted, because trusting the ledger alone lets it go stale when the boundary rule changes while recomputing alone would insert a boundary no human approved. It also refuses a gold whose sha256 differs from the `gold_sha256_before` the ledger recorded (the offsets were judged against a different corpus), asserts the other nine types stay byte-identical, insists the inserted count equals the EVT verdict count so a silent skip cannot pass as a recovery, and re-runs `gate` on the *new* gold so an insertion that breaks another site's classification surfaces here. `residue` applies the settled boundary clause to **every existing EVT span**, not only the ones ending in an axis-1 head — narrowing the population to the head list would measure the rule with the rule's own field of view. Existing mismatches are not retro-corrected (canonical 584 keeps them), so **the report itself is the gate**: a recovered site gains gold EVT history and leaves the site-scan population forever, which means a bad insertion is invisible to further recovery rounds and only this counter looks behind it. `과축소` (an unlabeled adjacent proper noun the span should have included) is report-only; `고유명삼킴` (an EVT span overlapping a labeled proper noun) exits non-zero, because flat BIO cannot represent it and the measured count is 0, so a nonzero one was created by an insertion. `fp-blindspot` is the only place model predictions enter, and only as a **diagnosis**: it counts the EVT false positives that look like `proper noun + event head` but have no site in the `gate` population, which names the shapes the head list cannot see. Its shape detector deliberately **does not consult the head list** — judging the shape with the list would drop every head the list is missing before the count begins, so the head is whatever the FP span's last eojeol reduces to. Widening the list from this diagnosis is allowed only *before* the head arm's F1 is observed, and the report enforces that order by fingerprinting the canonical **rule content** (the four parsed parameters — not the whole file), the head list, the gold and every prediction file it read: change the list afterwards and the committed artifact contradicts itself. That enforcement covers widening the head list; a widening that lives in §5.3's prose instead (adjacency, head-matching mode) leaves the digest unmoved and needs its own lock. `rescore` re-scores **both arms against the same gold** — the base arm was scored on the pre-recovery gold, so putting its numbers beside the head arm's compares two rulers (the recovery moved the EVT denominator), and the fix is to keep the predictions and redo only the scoring. It also reports the **recovery-free subset** Δ (the rows the recovery touched removed), because the full Δ folds the handed-over answers into the gain. It exits non-zero if the two arms cover different rows or their fold partitions differ, since a mismatched partition still produces a plausible-looking paired Δ |
| `ko_split_audit.py` | Post-hoc audit of whether two arms of a past k-fold run actually shared fold membership (CLI: `audit`). paired statistics only hold when both arms partition the same sentences, but a stratified split reads labels to build its strata, so editing gold can rearrange every fold — and pairing by fold number afterwards still yields plausible-looking numbers. The split is a pure function of (row order, labels, seed, fold count, group key, stratify), so it regenerates **without training**; the judgement ledgers carry recovery coordinates and the gold sha256 of the moment, so past gold reverses too, and the committed fingerprint decides whether the reversal was right — span **counts** cannot, since reversing one span per EVT verdict makes the count match by construction. Four things are enforced rather than assumed — the gold reversal, the positive control, the base arm's basis, and the refusal to decide. A **positive control** re-derives the fold membership of a run whose prediction dump is supplied by the caller and demands 10/10 exact reproduction (the dumps the committed report used are no longer in the repo, so a rerun has to point it at a fresh run): this audit's expected answer is a *low* overlap, so a broken pipeline fails in the direction the hypothesis predicts and would pass silently without it. The overlap metric is `intersection / |base fold|`, deliberately **not** Jaccard, so the number sits beside the one `rescore` already reports instead of creating a second ruler for the same event. The base arm's setting must carry a documented basis (path:line) since that is the arm a document pins; the head arm's missing basis is the premise of the audit, not a violation. And the verdict refuses to choose: when the head arm's setting is not documented and the two scenarios disagree, it records `undecidable` and exits non-zero if a single verdict was written anyway — a guess recorded as a decision is invisible afterwards. When the two scenarios agree the setting cannot change the answer, so it decides without a basis. Thresholds (`<0.20` broken, `≥0.90` matched) are module constants fixed before measuring |

| `data/evt_axis1_prereg.json` | What was already fixed when the head arm started training — sha256 of canonical, the head list, the judgement ledger, the promoted σ and pooled metrics, and each base fold's prediction dump. A test recomputes the ledger and the promoted metric files byte-for-byte and canonical by rule content — the fold-dump hashes stay as a record only, since those dumps were dropped — so a later change to the measured inputs or the noise band breaks the artifact instead of quietly re-dating it. **canonical is checked by rule *content*** (`canonical_rule_sha256()` over the head list, proper-noun label set, guard thresholds and reason-code names), not by hashing the whole file: a file hash cannot tell widening a head from adding a measurement footnote, so every legitimate edit to the document would break the test, and the only way to unblock it would be re-dating the fingerprint — which turns the pre-registration into a value that can be refreshed at will. The whole-file `canonical_sha256` stays as a record of what the document looked like then, but nothing compares it to the current file. **The digest measures exactly four things** — head list, proper-noun label set, guard thresholds, reason-code names — and **nothing else in §5.3**. Measured non-coverage (head matching `끝나는`↔`포함하는`, how the proper-noun basis is composed, the adjacency condition, the axis-3 boundary clause, the excluded-modifier list) all leave the digest unmoved, and that list is *not* closed — §5.3 is prose, so the number of rules it states is open. ## For AI Agents

### Working In This Directory
- Prompt engineering is the primary quality lever — `ner_prompts.py` contains highly tuned Korean linguistic rules. Do not simplify
- `spans_to_bio()` (public, defined in `llm_helpers.py` — shared across ko/ja/vi, not ko-local) uses 2-pass matching: exact token match first, then substring containment (handles Korean particles like "서울에서" matching "서울")
- `split_sentences()` splits on `.!?` followed by whitespace, minimum 10-char buffer — defined once in `llm_helpers.py`, called via the shared base classes
- vLLM sends all sentences concurrently (`concurrency`, default 32)

### Testing Requirements
- Test span-to-BIO alignment for Korean compound entities with particles
- Mock `AsyncOpenAI.chat.completions.create()`

### Common Patterns
- The labeler imports prompts from `ner_prompts.py`
- `DEFAULT_ENTITY_TYPES = ["PER", "LOC", "ORG", "DAT", "PROD", "EVT"]`

### Internal
