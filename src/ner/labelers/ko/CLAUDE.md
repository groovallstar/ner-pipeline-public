# ko

## Purpose
Korean NER labelers aligned to the canonical schema with the NER 5 types (PER=person, LOC=location, ORG=organization, PROD=product/work, EVT=event) plus DAT=date. PER/DAT are renamed from KLUE (PS/DT) with KLUE's TI/QT dropped and still follow KLUE NER guidelines (particle exclusion, syllable boundaries, compound merging).

**LOC/ORG do NOT follow KLUE guidelines — they follow the narrow-ORG redefinition.** `ORG` covers government/administrative/public/political bodies only (ministries, agencies, commissions, parties, labor unions, state enterprises, international bodies, legislatures, plus metonymic government-building names). Man-made facilities and venues (stations, airports, hospitals, universities, stadiums, museums) and non-governmental organizations (private companies, broadcasters/press, sports clubs and leagues, military units, courts/prosecution, religious bodies) are **not extracted at all** (non-entity). `LOC` likewise covers only administrative divisions, natural place names, and addresses — building and facility names are dropped. Single source for this rubric: `docs/manual/data/canonical-entity-schema.md` §KO and `docs/manual/data/korean-entity-labeling-rules.md`.

Consequently **KO's LOC/ORG extension differs from JA·VI** — JA·VI canonical absorbs every man-made facility into ORG, while KO discards those same facilities. Do not compare ORG numbers across languages without accounting for this.

PROD/EVT: continuously operating leagues and clubs ("프리미어리그", "메이저리그") are private sports organizations, so they are non-entity rather than ORG; only a specific edition of a competition or a specific match is EVT. Laws, era labels, multi-year states/processes (냉전, 산업혁명), and abstract disputes are non-entity too. The PII types remain unfilled (later increments).

Two backend implementations (vLLM, OpenAI) encode the same rules in **two different templates** — vLLM uses `SINGLE_PROMPT_TEMPLATE` (many few-shot examples), OpenAI uses `SYSTEM_PROMPT` + `USER_PROMPT_TEMPLATE` (condensed, no examples). Editing the rules on one side only makes the two backends disagree. span-to-BIO conversion logic is shared.

| `klue_to_canonical_gold.py` | KLUE BIO → canonical char-span gold JSONL conversion (CLI) |
| `ko_prod_evt_relabel.py` | PROD/EVT LLM relabel incremental pipeline (CLI: relabel\|merge) |
| `ko_evt_r2_audit.py` | EVT gold audit against the canonical §5.3 rules + R2 recovery (CLI: audit\|judge\|apply\|homomorph\|head-candidates). `audit` is a **re-runnable machine gate** — it reports the R2 coverage rate and rule violations and exits non-zero via `--gate-rate`/`--gate-violations`, so the same command verifies gold before and after a recovery. `judge` asks two independent LLMs per occurrence and keeps only unanimous verdicts; `apply` inserts them and fixes deterministic violations, asserting the other nine types stay byte-identical. `head-candidates` scans gold with the canonical R2 head list — **model predictions are never an input**, because a candidate pool drawn from model FPs grows gold only where the model already fired, which guarantees a recall gain by construction. `homomorph` is the issue #201 consistency gate: every head-homomorph surface with no gold EVT history must be recovered, excluded by a canonical reason code, or judged NOT — it exits non-zero on anything left unclassified |
| `ko_evt_axis1_audit.py` | Axis-1 compound (`proper noun + event head`) head enumeration and site scan (CLI: head-survey\|sites\|codes\|gate\|apply). `head-survey` **does not let the author pick the candidate set** — it aggregates **every** eojeol inside gold EVT spans (not just the span-final one: `마라톤` sits mid-span in `보스턴 마라톤 대회 폭발 사건` and is invisible to a final-eojeol count, and `폭발`·`붕괴`·`화재` fall below the threshold the same way), keeps those appearing at least `--min-count` times that are standalone corpus nouns with **no proper-noun label history** — that last filter drops the modifier half of the same span (`보스턴`) while keeping the head — and attaches corpus evidence (homomorph types, gold EVT history, other-type labels, whether a shorter candidate already covers it) so canonical can assign an adopt/exclude reason code to *every* candidate. A low EVT-history ratio is ambiguous by construction — it means either a lexical-boundary leak (`분위기` under `위기`) or bulk under-recovery (`교통사고` under `사고`) — so the homomorph list is reported alongside the ratio and a human reads it. `sites` enumerates candidate **sites** (row, span) for a given head list: the proper noun may sit inside the word (`서울월드컵`) or in the preceding eojeol, and a preceding proper noun carrying a particle is rejected (`파리에서 테러` is a sentence constituent, not a compound). Overlap with existing gold EVT spans is measured (`exact`/`inside_longer`/`partial`/`none`), never silently dropped, so absorption stays distinguishable from recovery. Its report fingerprints both the head list and the gold file, so a changed population says *which* input moved. `codes` is the reason-code ledger — enumeration is reproducible but **assignment is human**, which is where selection bias could live, so every candidate must carry a canonical code and `--gate` exits non-zero on any left unassigned. `parse_canonical_axis1()` reads §5.3 for *all* population-deciding parameters (head list, proper-noun label set, length/ratio guards, reason-code names) and tests compare it against the module constants: the rule lives in the locked ruler file while this enforcing module does not, so narrowing a head — or quietly moving one from adopted to excluded, which the ledger gate alone would pass — fails the sync test. `gate` is the main consistency gate and it counts **sites, not surfaces** — the same surface gets different verdicts in different rows (`세월호 사고` is an event in one row and part of a committee name in another), so folding by surface lets one row's honest verdict absolve another. Every site must land in one of five buckets — recovered · canonical-excluded · judged NOT · absorbed by a longer gold EVT · type-clash-recorded — and anything left over exits non-zero. The type-clash bucket exists so a site whose head is already covered by a non-EVT gold span has an exit other than "write NOT in the ledger"; without it the only way to green the gate is a forced verdict, and a human judgement that can only go one way is a formality. Recovery count is reported alongside, because if every site is excluded or absorbed then **zero recoveries also passes every check** — a near-zero count is itself a signal to re-examine. The insert span implements the canonical axis-3 boundary clause: a labeled adjacent proper noun is never swallowed (the span is trimmed to the head), and if the head itself is covered the site is a clash rather than an insertion. `apply` inserts the ledger's EVT verdicts and requires **the ledger and the current rule to agree on the boundary** — the site is rescanned, matched by its detection span, and a ledger row whose insert span no longer matches is counted and refused rather than inserted, because trusting the ledger alone lets it go stale when the boundary rule changes while recomputing alone would insert a boundary no human approved. It also refuses a gold whose sha256 differs from the `gold_sha256_before` the ledger recorded (the offsets were judged against a different corpus), asserts the other nine types stay byte-identical, insists the inserted count equals the EVT verdict count so a silent skip cannot pass as a recovery, and re-runs `gate` on the *new* gold so an insertion that breaks another site's classification surfaces here |
| `data/evt_axis1_judgements.jsonl` | Per-site provenance for the axis-1 compound recovery — **22** decisions (14 EVT / 8 NOT), each with its own reason, the boundary reason that fixed the insert span, `evidence` (what the following text proves), judge, draft model, round tag and gold sha256. ## For AI Agents

### Working In This Directory
- Prompt engineering is the primary quality lever — `ner_prompts.py` contains highly tuned Korean linguistic rules. Do not simplify
- `spans_to_bio()` (public, defined in `llm_helpers.py` — shared across ko/ja/vi, not ko-local) uses 2-pass matching: exact token match first, then substring containment (handles Korean particles like "서울에서" matching "서울")
- `split_sentences()` splits on `.!?` followed by whitespace, minimum 10-char buffer — defined once in `llm_helpers.py`, called via the shared base classes
- vLLM sends all sentences concurrently; OpenAI uses token-budget batching

### Testing Requirements
- Test span-to-BIO alignment for Korean compound entities with particles
- Mock `AsyncOpenAI.chat.completions.create()`

### Common Patterns
- Both labelers import prompts from `ner_prompts.py`
- `DEFAULT_ENTITY_TYPES = ["PER", "LOC", "ORG", "DAT", "PROD", "EVT"]`
