# refuter — 격리 컨텍스트 반박자

완료 직전, **기억이 깨끗한 서브에이전트**를 띄워 현재 변경을
*승인이 아니라 반증*시킨다. 산출물을 만든 본인(메인 세션)이 자기 답을
후하게 보는 self-preferential bias를 피하는 게 목적이다. 모델은 diff
위험도로 자동 선택한다(기본 Sonnet, 측정-타당성 위험 diff는 Opus — 아래
§모델 선택).

## 언제

- Stop 게이트(`.claude/hooks/refuter_gate.py`)가 block reason으로 반박자를
  요청할 때 (루프 모드 + 미커밋 diff + ruff 통과 상태).
- 또는 완료 직전 산출물을 한 번 더 적대적으로 점검하고 싶을 때(수동).
- **정의 시점(3단계 직후)**: eval·metric 이슈에서 기준 확정 직후·구현
  전에 eval 설계를 적대적으로 점검할 때 — diff가 아니라 *설계*를 반증
  (아래 §정의-시점 모드).

## 절차

1. **diff_hash 계산** (게이트와 동일해야 판정 파일이 매칭된다):
   ```
   git diff HEAD | sha256sum   # 앞 12자
   ```
2. **기준 출처 확보**: 가장 가까운 `docs/issues/issue-*.md`의 계획/성공
   기준 섹션, 또는 활성 PRD(`.omc/state/sessions/<id>/prd.json`)의
   acceptance criteria. 없으면 직전 사용자 요청을 기준으로 삼는다.
3. **반박자 spawn** — Agent 툴, 격리 컨텍스트, `model`은 **§모델 선택**
   규칙으로 정한다(기본 `sonnet`, 측정-타당성 위험이면 `opus`):
   - OMC 환경이면 `subagent_type`을 `code-reviewer`(또는 더 적대적인
     `critic`)로 지정해 OMC 검증-위임 정책(approval pass는
     code-reviewer/verifier)과 정합시킨다. 미설치 시 기본 서브에이전트.
   - 역할: **반증 전담.** 승인하지 말 것. "문제 없음"을 증명하지 말고
     "기준 미충족·회귀·오염"을 찾아내려 시도하라.
   - 검증 축은 **도구가 확정할 수 없는 것**뿐이다. 리터럴 수치 대조와
     테스트 삭제·`skip`·assert 약화 검출은 게이트의 결정적 층이 이미
     수행했으므로 다시 세지 말라:
     - **(a) 코드 정합성·회귀**: diff가 기준을 실제로 충족하나? 숨은
       회귀·엣지케이스 누락은?
     - **(b) 측정 타당성**(이 프로젝트의 핵심 위험): 숫자가 다 맞아도
       결론이 틀릴 수 있는 지점 — gold/eval 세트 변조, 시드·분할 누수,
       "수치가 올랐다=개선"의 인과가 순환·교란·인플레인가. 표 밖 산문의
       파생 수치(Δ·σ)는 게이트가 못 보므로 여기서 본다.
     - **(c) 테스트 의미 보존**: 게이트가 센 것은 개수뿐이다. 남은
       테스트가 *같은 계약*을 검증하나, 약한 명제로 갈아탔나?
   - 범위 제한(비용·5분 캐시 TTL): diff + 기준만으로 판단하고, 특정
     주장을 검증할 때만 파일을 read 하라. 저장소 전체 탐색 금지.
4. **판정 기록** — 반박자가 직접 Write 한다:
   `.omc/state/refuter/<diff_hash>.json`
   ```json
   {"verdict": "PASS" | "FAIL",
    "diff_hash": "<앞 12자>",
    "findings": ["...", "..."],
    "model": "sonnet | opus",
    "round": 1}
   ```
5. **후속**:
   - PASS → 완료 진행(게이트가 통과시킨다).
   - FAIL → findings를 수정한다. 코드가 바뀌면 diff_hash가 달라지므로
     게이트가 새 판정을 다시 요구한다(같은 결함 재발 방지).

## 정의-시점 모드 (설계 반증)

위 절차는 *결과 시점*(완료 직전 diff)이다. **정의 시점**은 diff가 아직
없으므로 게이트가 아니라 **리뷰**다:

- 입력 = 수락 기준 + eval 설계(split·group-key·metric·임계)의 *텍스트*.
- 반증 대상 = *형식*만: falsifiable한가, gameable한가, eval이 구조적으로
  누출-free인가. 의도("무엇을 중시하나")는 사람 고유라 대상 아님.
- 출력 = **findings를 사람에게 보고**(판정 파일·diff_hash 없음). 사람이
  기준에 반영한 뒤 구현 착수. 모델 선택·반증 자세는 결과 시점과 동일.

## 모델 선택 (Sonnet/Opus)

기본 **Sonnet**. 반증이 *대조*로 끝나면(숫자↔`certified/*.json` 일치, 국소
코드 회귀, 테스트 삭제·약화 여부) 충분하다.

**Opus로 격상하는 기준은 하나** — *틀린 답이 그럴듯해서 통과할 위험*, 즉
반증에 **적대적 추론**이 필요할 때. 수치가 다 맞아도 결론이 틀릴 수 있는
경우다. 흔한 신호(규칙 아닌 예시): 측정의 입력(gold/eval)이나 측정 코드
(메트릭·분할·누출)가 바뀜 / "수치가 올랐다=개선"의 인과가 비자명(순환·교란·
인플레) / 변경이 넓어 한눈에 회귀를 못 짚음.

그 외는 Sonnet. 판정 JSON `"model"` 필드에 실제 모델을 기록한다.

## 게이트의 결정적 층 (반박자가 다시 하지 않을 것)

게이트(`.claude/hooks/refuter_gate.py`)가 반박자를 부르기 **전에** 0토큰
으로 통과시킨 검사다. 판정 파일이 요구되는 시점엔 이미 전부 PASS다.

| 검사 | 대상 |
|---|---|
| 기준 파일 잠금 | 정답·채점규칙·분할 정의 파일 변경 → 사람 `ack` 없으면 차단 |
| ruff | 변경된 `.py` |
| 테스트 무결성 | `git diff` 의 test 함수 순삭제 · 무조건 `skip`/`xfail` 추가 · assert 순삭제 (`skipif` 는 환경 조건부라 제외) |
| 인용 수치 대조 | `docs/reports`·`docs/issues` **표 안** 수치 ↔ `certified/**` |

오탐은 사람이 `ack-<diff_hash>` 로 해제한다. **반박자가 ack 파일을 만들면
안 된다** — 결정적 층의 소유권은 사람에게 있다.

수치 대조는 *존재* 검사라 우연 일치를 배제하지 못한다(자릿수가 낮을수록
검출력 하락). 게이트가 통과시킨 수치라도 **출처·인과가 타당한지는 반박자가
본다** — 특히 "수치가 올랐다=개선" 의 인과와 산문의 파생값(Δ·σ).

## 비용 메모

- 모델은 위 §모델 선택으로 자동(기본 Sonnet, 측정-타당성 위험 시 Opus).
  서브에이전트는 별 컨텍스트라 메인 캐시를 깨지 않는다.
- 느리고 넓게 읽으면 메인 세션 캐시 TTL(5분)을 넘겨 재진입 비용이
  10배 튄다. **빠르고 좁게** 유지하라.
- 결정적 층이 이미 세어 둔 것(리터럴 수치·테스트 개수)을 다시 세지 말고,
  *판단이 필요한 축*에만 토큰을 쓴다.
