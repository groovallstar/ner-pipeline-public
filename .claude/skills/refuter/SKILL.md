# refuter — 격리 컨텍스트 반박자

완료 직전, **기억이 깨끗한 서브에이전트**를 띄워 현재 변경을
*승인이 아니라 반증*시킨다. 산출물을 만든 본인(메인 세션)이 자기 답을
후하게 보는 self-preferential bias를 피하는 게 목적이다. 모델은 지정하지
않는다 — 세션 기본 모델을 그대로 쓴다.

## 언제

- Stop 게이트(`.claude/hooks/refuter_gate.py`)가 block reason으로 반박자를
  요청할 때 (루프 모드 + 미커밋 diff + ruff 통과 상태).
- 또는 완료 직전 산출물을 한 번 더 적대적으로 점검하고 싶을 때(수동).
- **정의 시점(3단계, 승인 전)**: 수락 기준을 적은 직후·구현 전에 그
  기준의 *형식*을 적대적으로 점검할 때 — diff가 아니라 *설계*를 반증
  (아래 §정의-시점 모드). **기준 파일을 건드릴 이슈는 이 호출이 필수**
  다(루트 `CLAUDE.md` §이슈 진행 절차 3단계).

## 절차

1. **diff_hash 계산** (게이트와 동일해야 판정 파일이 매칭된다):
   ```
   git diff HEAD | sha256sum   # 앞 12자
   ```
2. **기준 출처 확보**: 가장 가까운 `docs/issues/issue-*.md`의 계획/성공
   기준 섹션, 또는 활성 PRD(`.omc/state/sessions/<id>/prd.json`)의
   acceptance criteria. 없으면 직전 사용자 요청을 기준으로 삼는다.
3. **반박자 spawn** — Agent 툴, 격리 컨텍스트. `model`은 **지정하지
   않는다** — 세션 기본 모델을 상속한다:
   - OMC 환경이면 `subagent_type`을 `code-reviewer`(또는 더 적대적인
     `critic`)로 지정해 OMC 검증-위임 정책(approval pass는
     code-reviewer/verifier)과 정합시킨다. 미설치 시 기본 서브에이전트.
   - 역할: **반증 전담.** 승인하지 말 것. "문제 없음"을 증명하지 말고
     "기준 미충족·회귀·오염"을 찾아내려 시도하라.
   - 검증 축은 **도구가 확정할 수 없는 것**뿐이다. 리터럴 수치 대조와
     테스트 삭제·`skip`·assert 약화 검출은 게이트의 기계 검사가 이미
     수행했으므로 다시 세지 말라:
     - **(a) 코드 정합성·회귀**: diff가 기준을 실제로 충족하나? 숨은
       회귀·엣지케이스 누락은?
     - **(b) 측정 타당성**(이 프로젝트의 핵심 위험): 숫자가 다 맞아도
       결론이 틀릴 수 있는 지점 — gold/eval 세트 변조, 시드·분할 누수,
       "수치가 올랐다=개선"의 인과가 순환·교란·인플레인가. 표 밖 산문의
       파생 수치(Δ·σ)는 게이트가 못 보므로 여기서 본다.
     - **(c) 테스트 의미 보존**: 게이트가 센 것은 개수뿐이다. 남은
       테스트가 *같은 계약*을 검증하나, 약한 명제로 갈아탔나?
     - **(d) 테스트가 그 경로를 실제로 태우나**: "덮는 테스트가 있다"와
       "그 경로가 실행된다"는 다르다. 입력이 조건을 트리거하지 못하면
       (전 행이 임계 미만이라 분기 진입 0회 등) 통과는 커버리지 증거가
       아니다. 거절·예외를 "1건 이상 나왔다" 같은 느슨한 명제로 확인하는
       것, 계약을 선언만 하고 실행 경로에 배선하지 않은 것도 같은 결함이다.
   - 범위와 예산은 아래 §범위와 예산 이 정한다. **그 절을 프롬프트에
     그대로 넣는다** — 반박자가 자기 예산을 모르면 지킬 수 없다.
4. **판정 기록** — 반박자가 직접 Write 한다:
   `.omc/state/refuter/<diff_hash>.json`
   ```json
   {"verdict": "PASS" | "FAIL",
    "diff_hash": "<앞 12자>",
    "defects": ["막는 사유만 — 아래 §판정 규칙의 FAIL 조건에 해당하는 것"],
    "checked": ["확인했고 이상 없었던 것 · 등급을 매겨 통과시킨 것"],
    "model": "<실제로 돈 모델>",
    "round": 1}
   ```
   **둘을 섞지 말 것.** 검증 기록과 결함이 한 배열에 섞이면 사람이 판정
   파일을 훑을 때 볼 것이 몇 줄인지 알 수 없다. `defects` 가 비면 PASS,
   비어 있지 않으면 FAIL 이다.
5. **후속**:
   - PASS → 완료 진행(게이트가 통과시킨다).
   - FAIL → `defects`를 수정한다. 코드가 바뀌면 diff_hash가 달라지므로
     게이트가 새 판정을 다시 요구한다(같은 결함 재발 방지).

## 판정 규칙 — 무엇이 FAIL인가

**FAIL은 "결함이 있나"가 아니라 "잘못된 통과를 만드나"로 정한다.** 완벽한
변경을 요구하면 판정이 취향이 되고, 결함을 세기 시작하면 전부 통과시키게
된다. 기준은 하나 — *이대로 지나가면 틀린 결론이 참으로 기록되는가.*

**FAIL** — 그냥 두면 거짓이 사실로 남는다:

- 문서 수치가 산출물과 다르다 (표 안이든 산문의 Δ·σ든)
- gold·분할·채점규칙이 소리 없이 바뀌었는데 전후 비교를 그대로 주장한다
- 게이트·검증이 막아야 할 것을 통과시킨다 (**false-green**)
- 남은 테스트가 같은 계약을 더는 검증하지 않는다 (개수는 그대로인데 명제가
  약해짐 · 덮는다고 적힌 경로가 실행되지 않음)
- 수락 기준의 항목이 실제로는 구현되지 않았는데 됐다고 적혀 있다

**PASS + `checked` 에 기록** — 결함이 *안전한 쪽으로* 실패한다:

- 과도하게 막는다 (loud cheap fail — 시끄럽고 싼 실패)
- 현재 데이터·설정에서는 발현하지 않는다
- 불일치가 문서에 공개돼 있고 근거가 산출물로 확인된다
- 진단·분석 전용 경로라 채점에 유입되지 않는다

**애매하면 FAIL.** 한 라운드는 평균 486 만 토큰이다. 의심을 만들어 라운드를
정당화하지 않는다.

## 종료 조건

**라운드 상한은 3 이다.** 넘기면 남은 결함을 사람에게 넘기고 멈춘다. 게이트가
부르는 경로와 메인이 스스로 부르는 경로 양쪽에 걸린다.

**라운드 수는 디스크에서 센다.** 기억으로 세지 않는다.

```bash
ls .omc/state/refuter/*.json
```

**같은 자리가 두 번 걸리면 그 자리를 또 고치지 않는다.** 그 문장을 빼거나
그 주장을 안 하는 쪽으로 구조를 바꾼다.

**직전 판정 파일을 반박자에게 넘긴다.**

## 범위와 예산

**읽어도 되는 것**

- 현재 diff 전체
- 가장 가까운 `docs/issues/issue-*.md` 의 기준 절
- **diff 에 이름이 나온 파일** — 그 파일만
- `.omc/state/refuter/*.json` — 앞 라운드 판정
- 이미 있는 테스트 실행 (`pytest <경로>`)

**하지 않는 것**

- 코퍼스·데이터셋 전수 스캔
- 저장소 전체 grep 스윕
- 검증용 분석 스크립트 새로 작성
- diff 에 안 나온 파일 탐색

**예산은 Bash 20 회다.** 넘으면 멈추고 그때까지 본 것으로 판정한다. 못 본
것은 `checked` 에 `미확인: <무엇>` 으로 적는다.

**전수 스캔으로만 확인되는 주장은 세지 않는다.** `defects` 에 적어 사람에게
넘긴다.

> 이 수치를 검사하는 것이 없다. 테스트나 `certified/` 로 옮기거나 주장을 빼라.

## 정의-시점 모드 (설계 반증)

위 절차는 *결과 시점*(완료 직전 diff)이다. **정의 시점**은 diff가 아직
없으므로 게이트가 아니라 **리뷰**다:

- 입력 = 수락 기준 + eval 설계(split·group-key·metric·임계)의 *텍스트*.
- 반증 대상 = *형식*만. 의도("무엇을 중시하나")는 사람 고유라 대상 아님.
  - **집행 주체** — 기준마다 "무엇이 이걸 검사하나"에 답이 있나. 새 규칙을
    기준 파일에 넣으면서 그걸 볼 탐지기가 없으면, 구현자는 자기가 만든
    탐지기로 자기 규칙을 재게 되고 어긋나도 스스로는 안 보인다.
  - **기준 간 모순** — 한 기준이 다른 기준을 불가능하게 만들지 않나
    (예: "타입 오염을 교정한다" + "불변 타입 byte-identical").
  - **falsifiable · gameable · 누출-free** — 반증 가능한가, 자를 바꿔
    통과시킬 수 있나, eval 이 구조적으로 누출-free인가.
- 출력 = **지적을 사람에게 보고**(판정 파일·diff_hash 없음). 사람이
  기준에 반영한 뒤 구현 착수. 반증 자세는 결과 시점과 동일.

## 게이트의 기계 검사 (반박자가 다시 하지 않을 것)

게이트(`.claude/hooks/refuter_gate.py`)가 반박자를 부르기 **전에** 0토큰
으로 통과시킨 검사다. 판정 파일이 요구되는 시점엔 이미 전부 PASS다.

| 검사 | 대상 |
|---|---|
| 기준 파일 잠금 | 정답·채점규칙·분할 정의 파일 변경 → 사람 승인(`human-allow-<diff_hash>`) 없으면 차단 |
| ruff | 변경된 `.py` |
| 테스트 무결성 | `git diff` 에서 **파일별** test 함수 순삭제 · 무조건 `skip`/`xfail` 추가 · assert 순삭제 (`skipif` 는 환경 조건부라 제외) |
| 인용 수치 대조 | `docs/reports`·`docs/issues` **표 안** 수치 ↔ `certified/**` |

오탐은 사람이 예외 승인 파일 `human-allow-<diff_hash>` 로 해제한다.
**반박자가 이 파일을 만들면 안 된다** — 기계 검사의 소유권은 사람에게 있다.

수치 대조는 *존재* 검사라 우연 일치를 배제하지 못한다(자릿수가 낮을수록
검출력 하락). 게이트가 통과시킨 수치라도 **출처·인과가 타당한지는 반박자가
본다** — 특히 "수치가 올랐다=개선" 의 인과와 산문의 파생값(Δ·σ).

## 비용 메모

- 한 라운드 실측: 평균 486 만 input 토큰, 최대 1,180 만(82 턴 · Bash 44 회).
- 서브에이전트는 별 컨텍스트라 메인 캐시를 깨지 않는다.
- 느리고 넓게 읽으면 메인 세션 캐시 TTL(5분)을 넘겨 재진입 비용이
  10배 튄다. 무엇이 좁은지는 §범위와 예산 이 목록과 숫자로 정한다.
- 기계 검사가 이미 세어 둔 것(리터럴 수치·테스트 개수)을 다시 세지 말고,
  *판단이 필요한 축*에만 토큰을 쓴다.
